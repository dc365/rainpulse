# QC review extension 20260917, contract v1

This additive extension is based on commit `3b8035104061cfe2db9da654006cffe0007665c8`.
It does not rename or overwrite the frozen `qc-opensource-7.3.6` engine. An enabled
run must use a NEW profile_version/parameters_hash and records the extension
version `qc-review-20260917-v1`. Operational eligibility remains false.

## Polar source evidence

`SRC_REVIEW_*` arrays have native ray/gate geometry. Candidate membership, measured
support, source-fit support and action are separate. Continuous contrast scores
are not probabilities. IDs associate measured segments; an intervening missing,
valid-no-echo or noncandidate gate is never assigned a candidate or an action.
Weather and measured source conflicts are barriers. Source-supported additions
enter BWS_CANDIDATE_MASK and the existing P2 unified quarantine/budget policy;
there is no new REJECT/confirmed action. With the extension absent, historical output semantics and hashes are preserved by the integration recipes; full worker regression remains a deployment gate. Audit mode adds diagnostics without changing previous actions.

## Background v2

A sample explicitly supplies observed_mask and no_echo_mask. A no-echo gate can
have NaN DBZH and still contributes to the observed denominator. Missing gates do
not. An observed, detected gate must have finite DBZH. Input hashes, reviewed
clear-air labels, timezone-aware times, scan IDs, native geometry, radar config,
scan strategy and hardware version are mandatory. A prior is not a truth label.

One builder serves both former public construction entrypoints. The new asset
contains raw observation/hit/no-echo counts, per-gate distinct-day support,
day-balanced occurrence frequency with a day-level Wilson lower bound, DBZH/VR/SW
moments, exact native coordinates and UTF-8 JSON provenance encoded as uint8.
The digest is compatible with the existing sorted-array content digest. An asset
with 20 dates globally but fewer than 20 observed dates at a gate does not qualify
that gate. The 20-day/200-observation defaults are project acceptance settings,
not universal radar constants. Thresholds and semantics are versioned.

## Nonprecipitation classification

NP_CLASS: 0 unknown, 1 weather, 2 fixed_ground, 3 anomalous_propagation,
4 sea_clutter, 5 biological, 6 mixed_or_ambiguous, 7 missing,
8 below_no_rain_threshold (finite measured DBZH below the configured floor, NOT
proof of instrument no-detection).
NP_EVIDENCE_BITS identifies evidence families; NP_CLASS_BITS preserves competing
class hypotheses. NP_CONFIRMED_MASK is always zero in this extension.

Classification does not require a computable METEO_SCORE. Missing polarization
can only be compensated by distinct, verified history/temporal/Doppler/vertical
families. Zero VR, a sea mask, low RHOHV, absence in a high cut, persistence, or
small area alone never creates an action. Unsupported classes abstain.

NP_QUARANTINE_MASK is distinct from RFI_QUARANTINE_MASK. Its measured gates use
QC_ACTION=DOWNWEIGHT, LOW_QUALITY, QPE_ELIGIBLE_MASK=0 and all moment trust masks=0.
DBZH_RAW, DBZH_QC and VALID_MASK retain original observations. DBZH_USABLE is NaN
at quarantine. The old RFI state/cause is not repurposed as non-RFI clutter.
Audit mode changes no existing action, eligibility, trust, flags or quality.
A stored baseline projection permits validation of old and new stages separately.

## Context / lineage

Raw fixed-coordinate recurrence uses strictly past, distinct scans on identical
native geometry, not earlier QC masks. Motion-compensated and negative-vertical
support require explicit comparability and detection-limit inputs; their absence
is recorded, not interpreted as no weather. Sea asset absence likewise abstains.

The lineage CLI validates supplied immutable asset inventories against local
file bytes, dependency hashes, source times and product definitions, and traces
explicit measured contributions. Missing source indices are reported as a lineage
gap, never guessed. Composite reflectivity and Hybrid/QPE products cannot be
compared as identical products. Display thresholds never alter measurements.


## Shared multi-radar background registry

`rainpulse-clutter-registry-v1` is a small NPZ containing `__meta_json` only.
Every station in one mosaic generation uses the SAME registry URI/version/hash
in its QC profile. Each `(radar_id, radar_config_version)` selects exactly one
v2 background URI/content hash/hardware/strategy binding. Only that asset is
loaded. This avoids per-radar profile hashes accidentally failing the existing
mosaic generation-consistency gate. Registry metadata never substitutes a legacy
frequency map for a validated v2 history asset.

Native hardware/scan metadata, when present, must match. When absent, an explicit
operator registry binding to the immutable radar-config version is required;
its use is recorded in the receipt. It does not prove physical hardware state.
A hardware or scan-strategy change requires a new corresponding config binding.

## Actual grid and fusion provenance

Review Grid adds `SOURCE_RAY` and `SOURCE_GATE` int32, original QC row/gate indices,
`-1` at missing cells. Existing SOURCE_SWEEP selects the cut. The indices come
from the actual frozen Hybrid mapping, not a second approximate mapping.

Review Mosaic adds `CONTRIBUTOR_WEIGHT_<radar source code>` float32 arrays using
the exact weights in the linear-Z fusion. Missing cells have zero weights.
Contributor metadata records the Grid/QC asset IDs and QC parameter hash.
Weight sum must be one on valid cells and positive-weight count must equal the
existing CONTRIBUTOR_COUNT. The tracer refuses legacy assets without these
fields instead of inferring provenance from nearest-neighbour coordinates.

The extension does not change the QPE equation or turn Hybrid into a composite
maximum product. Inventory auditing can include QPE ancestry, but no QPE replay
or actual 08:24 asset alignment was performed for this delivery.
