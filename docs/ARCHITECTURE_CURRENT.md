# RainPulse 当前架构与维护入口

更新：2026-09-22。第三批源码基线：`beb34035240d9ebdc8a7180828e048a46fb4eccb`。
本文描述代码边界，不代表已经部署到 105，也不代表气象技巧或性能验收。

## 运行形态

默认目标是单个原生 Go 主程序（Web/API、接入、编排）配合长期运行的 Python
Workers。PostgreSQL 保存工作流与资产元数据，NATS 传递小任务／结果消息，对象
存储保存不可变原始与派生资产。React 只调用 Go。不上新工作流平台，不拆新的
BFF 微服务，不将算法逐任务改成子进程调用。

```text
React 工作台
  → Go HTTP / 共享类型化查询 / 周期视图
       → PostgreSQL：任务、状态、元数据
       → NATS：小消息、确认与重试
       → 对象读取：已提交资产
  → Python：解码 → 极坐标QC → 单站格点 → 拼图 → QPE
                                                → NowcastInput → LK → 产品
       ↘ 诊断、实验、回算与检验：按前两批约定限制资源和发布资格
```

当前 Phase 1 源码时序为六分钟，LK 输出 30 个时效至 +180 分钟；历史 RP 验收中的
五分钟／24 时效配置继续冻结以支持复现，不能把历史描述当成当前部署默认值。
STEPS、NowcastNet、训练及其业务资格仍按原有独立配置和门控执行；本批不修改。

## 职责与依赖方向

| 位置 | 职责 | 不应增加的职责 |
| --- | --- | --- |
| `apiapp` / `unified` | 组装共享依赖、运行生命周期 | 气象计算与隐式版本切换 |
| `api` | HTTP 参数、权限、状态码、既有契约转换 | 作为其它域模块的业务调用协议 |
| `readquery` | 有类型的运行／分析读取接口 | HTTP、SQL、环境读取、状态写入、第二套缓存 |
| `workspace` | 周期选择、谱系检查、视图聚合、降级语义 | 以“读取成功”推断 operational eligibility |
| `postgres` / 对象读取模块 | 持久化与资产完整性 | UI 选择状态与算法决策 |
| `qc_resources` | 几何、静态资料资源加载与审计 | 消息发布、分类阈值、伪造高度基准转换 |
| `qc_engine` | 上下文与算法证据／决策 | 反向导入 qc_worker |
| React hook / reducer | 请求生命周期／已提交页面快照 | 更换后台算法或绕过质量门控 |

原生入口创建一个 `readquery.Service`，API 与工作台共享它。先迁移五类高频读取：
预报目录、分析目录、分析详情、QPE 摘要、诊断包。工作台直接转换领域对象，
不再为这五类读取构造 HTTP 请求、编码JSON、再反序列化。

`query_legacy.go` 只服务未注入依赖的旧构造入口和测试；注入服务失败不会触发
兼容回退。产品／集合投影、区间计算代理和部分旧 Handler 复用仍存在，后续应
先补行为刻画再迁移。本批不声称所有 HTTP Handler 之间的调用都已清除。

## 数据与正确性边界

保留有效无雨、缺测、低质量三态，保持原始资料不变。读取优化不能绕过完成标记、
校验和、上下文时间与几何身份验证。展示周期、有效时间、地图资产必须属于同一
已提交快照；失效请求不能覆盖后来选定的周期。

第一批：有界调度查询、固定 QC 完成摘要、发布暂停和统一容器运维入口。
第二批：不可变 bytes 缓存、选择读取、后台通道和资源预算；启用方式仍遵循该批
文档与本机实际配置。本批不打开缓存、改变通道、调整线程数或覆写近站 profile。
第三批：共享查询、QC 几何资源解耦、页面分包／请求刷新职责与维护检查。

参考：`ARCHITECTURE_BATCH1_20260922.md`、`ARCHITECTURE_BATCH2_20260922.md`、
`ARCHITECTURE_BATCH3_20260922.md`。算法与交付约束继续以 `AGENTS.md` 及
`RainPulse_技术架构与实施方案_含雷达质控_v1.1.md` 为准。

## 配置与运维

`.env` 保管部署参数／凭据；BDP 或其显式本地替代提供业务设置；版本化 YAML
提供算法配置；Compose/systemd 管理生命周期和资源。不要再新增需要人工重复
填写的配置副本。更新 Go 和 Worker 仍使用已有构建与发布协调流程。

历史／实验结果不能因这次重构自动获得业务资格。禁止直接覆盖既有不可变资产；
任何代码与镜像更新都应保留前两批暂停、身份检查和资源池配置。
