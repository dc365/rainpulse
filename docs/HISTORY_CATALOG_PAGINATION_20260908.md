# 历史目录分页与时间范围筛选

## 根因与修复

历史目录曾只读取 `/analysis-cycles?limit=200` 一页。同一起报的多个
不可变计算版本占满这 200 条，工作台之后按时次合并，仅剩 23 个时次。
因此仅调整历史补算窗口不能解决这个列表截断问题。

- Analysis API 增加 `cursor / next_cursor`，按分析时间、创建时间、ID
  的降序全序进行 keyset 分页；不删除版本、不改变血缘。
- 工作台遍历所有分析页，再选择每个时次的可用版本。
- 工作台自己的时次列表也增加游标；主界面和后台重生成面板共用完整
  目录读取函数，防止超过 200 个独立时次后再次截断。
- 保留原有日期选择，新增北京时间开始/结束筛选与“全天”。时间边界
  包含所选分钟，切换日期恢复全天；空范围及反向范围有明确提示。
- 筛选只作用于已有结果，不查询原始文件目录，也不触发补算。
  “没有结果”不等于“没有源数据”；未处理源数据仍走原有处理流程。

分页不是冻结快照；并发新增的较新结果由下一次刷新发现。原有福建
测试日期及网格可见性限制不变。最新周期检查 `limit=1` 是有意的，
不要求读取全部历史；事件流仍配合客户端周期刷新恢复遗漏通知。

## 验证

已先运行失败测试，再修复并通过：

1. 200 个重复版本之后的上午分析仍能出现在目录。
2. 201 个独立时次能从工作台第二页取到最早一个。
3. 前端全天/区间筛选、空结果、反向时间范围。

另覆盖 API 游标传递及错误格式、前端重复游标/中途失败；PostgreSQL
集成测试用连接级临时表验证相同分析/创建时间的 201 个版本及更早时次，
不修改实际业务表。

```sh
bash scripts/go_control.sh test ./...
pnpm --filter @rainpulse/web test
pnpm --filter @rainpulse/web build
bash scripts/check_generated_contracts.sh
# 可选 PostgreSQL 集成；连接配置在仓库外注入
RAINPULSE_TEST_DATABASE_URL='<test-database-dsn>' bash scripts/go_control.sh test ./internal/postgres -run TestAnalysisKeysetSQL -count=1
```

Go 测试、52 项 Web 测试、前端构建及契约一致性均通过。真实 PostgreSQL
临时表测试通过。Web lint 无错误，保留已有的 localCaseDate 导出导致的
Fast Refresh 警告。

## 测试部署结果

仅原位更新 API 与 Web，未重启算法 worker，未重算或删除任何雷达数据。
部署后两项服务 healthy。强制刷新目录返回 123 个唯一时次，范围为
2026-08-28 北京时间 08:10 至 18:35；以每页 50 条读取得到 3 页，
合计仍为 123 个唯一时次，无 degraded_sources。

08:10 详情包含可用 QPE 与雷达质控诊断；该起报的 LK/STEPS/NowcastNet
预报仍为 unavailable，不伪装成已完成。恢复历史目录不等于为每个时次
补齐所有算法。

桌面浏览器已实际核对新版面板的 123/123 时次、08:10–18:35 范围及
上午 QPE 显示，控件与面板布局无溢出。浏览器扩展自动化连接超时后
改用原生窗口检查；时间输入的自动化交互不稳定，区间行为由组件测试
验证，窄屏尚未完成截图验收。
