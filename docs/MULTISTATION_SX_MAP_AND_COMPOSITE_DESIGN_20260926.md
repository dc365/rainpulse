# 多站 S/X 同图与组合反射率设计

状态：设计稿，待实施。依据：用户 2026-09-26 要求，保持现有 S/X 地图、色谱、时间轴及纯数字距离圈。

## 1. 推荐方案

沿用一个雷达工作台，提供“单站质控 / 多站叠加 / 组合反射率”三个任务入口。多站叠加默认一张地图；组合产品默认一张地图，点击“对比”才展开左右联动地图。共用站点选择、目标时刻、地图视角和反射率色谱。

最小可用方案是把现有单站地理图层扩展成一个地图中的图层列表；先交付多 S、多 X、混合 S/X 叠加和已有 S 产品查看，再独立交付同口径 S/S+X 组合对照。无需新增地图框架、服务、账号或密钥。

不采用“每站开一个地图”的方案，多站时难以判断空间重叠，也不利于统一时间。透明图层的叠放只用于观察；组合产品由计算端从数值场生成。

## 2. 页面布局与操作

```text
质控排查                    单站质控 | 多站叠加 | 组合反射率
站点：已选 6 站 ▾             原始 | 质控后 | 对比       图层 ▾
┌─────────────────────────────────────────────────────────┐
│                                                         │
│              一张底图 + 多个站点回波图层                  │
│                                                         │
│  站心标记       当前关注站的距离圈          定位全部站点    │
└─────────────────────────────────────────────────────────┘
公共 dBZ 色标                          底图 / 距离圈 / 复位
历史日期       播放       ───── 唯一六分钟时间轴 ─────
```

- “站点”改为可搜索的多选面板，按 S、X 分组；支持组内全选/清空、S 全部、X 全部、S+X 全部。未选择的站也可在目录中查看可用状态。
- S/X 是站点筛选条件，不再作为互斥开关。已选站点在切换筛选时保留，面板顶部显示总数和各波段数量。
- 多站模式默认“质控后 + 单图”；切“原始”替换同一组站点的数据，点“对比”显示左原始/右质控后。左右拥有相同站点集合、顺序、仰角选择和地图视角。继续提供卷帘与单图。
- 仰角属于每个站点，不设跨站共用的扫层编号。首次选择默认该站最低可用仰角，图层行可修改并记忆。组合反射率使用规定高度范围内的全部合格扫层，不跟随 PPI 仰角下拉框。
- 图层面板默认收起；展开后每站一行：显隐、S/X、站号、真实仰角、观测时间、状态；透明度、置顶/置底收在该行展开区。
- 默认 S 组在下、X 组在上，组内按站号稳定排序；后加入站点不改变其他站点顺序。默认回波不透明，缺测透明。用户降低透明度时显示“透明叠加”，颜色混合不可作为 dBZ 读数。
- 点查弹出各可见站在该点的值、仰角及观测时刻；不从屏幕混合颜色反推数值。可先定位并突出某一站，再切入其单站质控。
- 地图始终显示所选站心。距离圈默认只画当前关注站，避免多个站的圈和数字互相覆盖；支持“关闭 / 关注站 / 全部”。圈标签保持纯数字，单位 km 在图层详情解释。
- 增删站点和切产品保留视角；“定位全部”显式适配所选站点有效覆盖范围。时间切换不自动缩放地图。
- 窄屏把站点和图层面板放进抽屉；默认单图，比较时上下排列，时间轴和色标仍只有一套。

## 3. 组合反射率的使用方式

进入“组合反射率”后，原始/质控后切换替换为产品选择：

| 产品 | 默认展示 | 说明 |
|---|---|---|
| S 组合反射率 | 一张地图 | 当前目录中有身份、聚合口径和地理定位的 S 结果 |
| S+X 组合反射率 | 一张地图 | 使用合格 S/X 数值输入生成的组合结果 |
| S 与 S+X 对比 | 左右联动或卷帘 | 同一次比较任务的 S-only 与 S+X 两份产品 |

- X-only、S+X−S 差值、来源站/波段、有效层数和观测年龄收进“分析图层”，不再增加顶层页面。
- 差值只在两份产品同时有效的格点计算；X 补充的新覆盖区单独着色，缺测不视作 0 dBZ。
- 产品摘要只放目标时间、实际参与站数和候选状态；点开可看来源站、排除原因、算法版本、网格及输入时刻。
- 组合产品的“参与站点”来自产品清单。改变地图图层显隐不改变已生成数值产品。修改计算站点集合后显示“站点选择已变更”，点击“生成所选站点组合”冻结任务；完成前继续显示旧结果及其原参与站清单，不冒充新选择结果。
- 首次默认查看已发布的全站产品，避免每次勾选站点就重算。自选站集合按配置/输入摘要复用同一结果。

## 4. 产品口径和已有代码

当前 `analysis:dbzh_qc` 的前端标题为“雷达组合反射率”，但代码有不同生成路径：

1. `radar/mosaic.py`：QI 等权重下的线性 Z 拼图，再转回 dBZ。
2. `diagnostics/renderer.py` 的全范围图：可替换为跨扫层、跨雷达最大有效反射率，记录 `aggregation=maximum_eligible_over_sweeps_and_radars`。
3. `multiband/fusion.py`：在固定 MSL 高度层按质量、年龄和分辨率等选择合格观测，随后取垂直最大值形成 `CR_DBZH`。

必须读取资产的 aggregation、algorithm/config version、输入列表识别真实语义，不能凭标题或 panel_id 认定它们相同。不把 QI 拼图重新命名为柱最大反射率，也不将已有 S 诊断 CR 与另一算法的 S+X CR直接作增益差值。

正式 S/S+X 对照复用 multiband 引擎：冻结同一网格、层高、目标时间、输入截止时间和 QC 版本；分别运行 S-only、X-only、S+X，S 输入保持一致。已有 `sx_comparison_objects` 可产出相应数组和快视图，继续补齐地图资产、统一产品目录和数值点查。

不直接平均 dBZ。数值融合、质量选择和空间采样继续由 Python 执行，React 仅显示经 Go 发布的产品。

## 5. 候选显示与计算资格

本方案修订旧设计中“未核验 X 一律不能跨站叠图”的显示限制：既有候选 X 地理资产可加入多站地图做位置和 QC 排查，图层列表以小标记注明“候选”。无 CRS/bounds、身份不符或缺坐标的图层不加载，说明具体原因。

这不改变计算资格。高度基准、波束、标定等不满足网络配置要求的 X 站不能进入可信组合。目录须分别返回 `display_status`、`composite_status` 与原因，避免一个总开关把所有功能一起禁用。

如果请求 S+X 而 X 没有合格贡献：仍可显示有效 S 结果，但标题明确为“S 组合 · X 未参与”，并列出原因。分别报告输入波段、有效覆盖波段、最终格点获胜来源波段；“已选 X”不等于“X 已贡献”。候选组合不得自动替代 QPE/预报输入。

关键假设：更多站点存在已登记、可定位的扫描与质控产品。目录覆盖全部站点，即使只有部分站有图件；缺图件的站显示可选状态和原因，不通过静态写死站点或假图补齐。

## 6. 时间与缺测

- 一个 UTC 目标时间 T，页面显示北京时间，默认六分钟步长。
- 历史 PPI 叠图沿用六分钟资料窗口：X 按体扫开始时间进入 `[T,T+6分钟)`，同站多份时选距窗口起点最近者；S 由对应分析周期解析实际 raw/QC 扫描。显示真实起止时间与偏差，标签为“资料窗口”，不称严格同时观测。
- 组合反射率使用产品的 `analysis_time`，标签为“分析时次”。按现有数值引擎的因果时间和网络年龄阈值选择输入，剔除目标时刻之后的射线及过期观测；输入可得性按冻结 cutoff 记录。历史重算不冒充当时实时可得性回放。
- 六分钟抽样不会把 X 原始一分钟观测变成六分钟有效观测。沿用经版本化的年龄配置；不为填满地图而自动延长。若抽样导致某时次 X 无可用贡献，展示原因，保留 S 可用结果。
- 每站 raw/QC 绑定同一扫描、扫层、结果版本。新时刻载入时旧帧不得继续标为新时刻；缺测和失败只影响相应站点，其他可用站继续展示。
- 同批多图层按目标选择代次提交，取消过时请求。对比图的同站 raw/QC 成对就绪；时间轴显示可用/部分可用/无数据，展开才看每站轨道。

## 7. 数据接口与组件改造

预计涉及超过 8 个文件，复用现有 Go、Python Worker、对象存储和 React，不新增服务。

```text
统一站点目录 + 时间/站点选择
             ↓
Go 图层解析 / 产品目录 / 点查 / 任务计划
       ↓                         ↓
对象存储地理资产          现有 Python Worker 数值组合
       ↓                         ↓
共享地图图层列表 ← Go 发布结果和来源清单
```

- 扩展 `/api/v1/workspace/radar-stations`，支持 band=S/X/all，统一目录和分页，不依靠前端 S 静态表作为全集。
- 新增只读 `POST /api/v1/workspace/radar-layer-resolutions`：接收目标窗口、站点集合、每站扫层选择；返回每站 raw/QC/flags、scan/result/sweep identity、观测时间、地理元数据、状态和原因。保留既有单站接口兼容旧链接。
- 新增 `GET /api/v1/workspace/radar-composites` 与 `/{id}`：按产品种类、时次、站集合摘要检索；返回地理资产、聚合方式、comparison_group_id、grid/algorithm/config/source identity、参与/排除清单、贡献统计、候选状态。
- 新增 `POST /api/v1/workspace/radar-layer-probes`：批量返回指定图层在一个经纬点的原始数值和来源，接口只交换小结果，不传完整雷达数组。
- 组合生成沿用 `/api/v1/admin/ops/plans` 与 submit；复用现有 `sx_composite` 计划，显式冻结所选站集合与分析时次。
- 扩展 `RasterGISMap` 接收 `layers[]`、`radarContexts[]`、`activeRadarID`；旧 `imageUrl` 经兼容适配转为单图层。按 stable layer_id 增删 ImageLayer，避免重建地图。
- 拆出 `RadarLayerPicker` 管理筛选/多选、`RadarLayerList` 管理显隐/顺序，`RadarCompositeView` 管理产品选择与比较。保持既有 CSS 变量、按钮、SharedTimeline、ReflectivityLegend。
- 每份组合资产须有 CRS、bounds/transform、像素尺寸、透明缺测、palette version、来源摘要；投影网格快视图须经计算端正确重投影后才作为 EPSG:4326 图层发布。
- 单站旧 URL 不变；多站链接记录站集合、每站扫层、目标时间、模式、布局、顺序和产品身份。不同站组合使用同一份冻结比较任务做差值。

OpenLayers 已有图层分组、显隐、透明度及卷帘机制，采用现有能力，不更换地图引擎：
- https://openlayers.org/en/latest/examples/layer-group.html
- https://openlayers.org/en/latest/examples/layer-swipe.html

## 8. 性能、失败与实施顺序

- 首批验收负载为 4 个 S + 11 个 X 候选站；只加载已选且可见的站，图片并发最多 4，预取最多下一个时次，总缓存按解码后字节控制在 128 MiB，当前帧优先。
- 不预加载所有仰角；不在滑动时间轴的每一个中间位置发完整请求。离开模式释放不用的图层和像素缓存。
- 单站失败保留其他站。产品不存在时显示“未生成”，提供计划入口；新任务失败继续保留原结果身份和失败原因。外部底图失败沿用现有海岸/网格参考，不阻断回波。

1. **多站同图 + 现有 S 产品查看**：统一目录、图层列表、混合选站、原始/质控切换、关注站距离圈、时间匹配；S 产品按记录展示真实名称。可独立上线。
2. **同口径组合产品与对照**：扩展地理资产与目录，接入同批 S-only/S+X，支持组合任务、双图/卷帘、缺 X 的准确状态。计算资格不足的站保留原因。可独立上线。
3. **贡献分析和交互完善**：数值点查、差值、新增覆盖、来源波段/站、年龄及质量；进一步验证多站动画负载。

各批先在本地完成测试、合入 main，再部署 105。保留既有单站接口和产品，新增资产以新版本原子发布；回滚运行制品即可恢复旧界面，不修改原始资料或删除旧结果。

## 9. 验收

- 同一张地图能显示多个 S、多个 X、以及混合 S/X；隐藏/置顶一站不改变其他站数据，改变波段筛选不丢已选站。
- 多站 raw/QC 对比站集一致，仰角按站独立；关注站圈标签纯数字，全部圈模式不会自动开启。
- 切时次、扫层、布局及快速连续请求，旧扫描不会贴上新时刻标签；缺测站留空且可解释。
- 查看 S、S+X 与左右对照，来源与聚合语义明确；严格同组同网格产品才可生成差值。
- 在人工格点样例验证 S-only、X-only、混合获胜来源、垂直最大值；无 X、X 全被剔除、有效无回波、缺测、过期、未来射线均有明确结果。
- ZF101/ZF505 真实样本先验收；11 个 X 站以目录接入状态如实显示，不能把目录发现等同于已有地图/组合。
- 1440px 与 375px 检查地图、色标和时间轴；4S+11X 条件下测加载时间、内存峰值和连续播放，报告实测值。
- 运行 `pnpm --dir apps/web test`、`pnpm --dir apps/web lint`、`pnpm --dir apps/web build`、`bash scripts/check_generated_contracts.sh`；后端运行相关 Go operations/workspace 测试与 Python multiband 测试，并验证实际产品来源与资产完整性。
