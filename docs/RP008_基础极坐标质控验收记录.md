## 阶段结论

RP-008 基础极坐标质控的真实垂直链路已完成，并部署到 测试服务器。系统能够
读取 RP-006/RP-007 产生的只读 `NormalizedRadarVolume`，在 RP-007 雷达健康
门控之后执行基础极坐标质控，写入独立且按算法版本隔离的 `QCRadarVolume`，再将
QI、标志位、模块溯源和诊断指标幂等写入 PostgreSQL，并通过 Go API 和 React
雷达运行台展示。

本次结论是“核心真实链路验收通过”，不是“所有质控模块已经业务验收”。静态地物
杂波、海杂波/AP、DEM 遮挡、衰减与标定模块的算法边界或接口已经预留，但缺少正式
版本化资产、标定资料和代表案例，因此本次真实运行中明确标记为 `skipped`。这些
模块不能因为输出计数为 0 就被解释为样本不存在相应异常。


## 已实现能力

### 配置、标志和算法

- `configs/qc/rp008-basic-v1.yaml` 保存健康门控、回波状态、径向干扰、静态
  杂波、海/AP 和 QI 阈值，并由严格 JSON Schema 校验。
- `configs/qc/flag-definitions.yaml` 定义版本化 uint32 `QC_FLAGS`，区分缺测、
  无雨、低质量、径向干扰、地物杂波、海杂波/AP 等状态。
- 不覆盖归一化输入，不删除原始仰角层，不把算法剔除回波改写为无降水。
- 合法但不含 DBZH 的体扫层仍保留原始射线和距离库几何；其 DBZH 为 NaN、
  `VALID_MASK=0`，并设置缺测标志。
- 每个模块记录执行状态、算法版本、输入/输出变量、修改掩码和诊断统计。
- 输出包含校正后 DBZH、`QC_FLAGS`、`QUALITY_INDEX`、有效掩码、QI 分量和
  `qc/summary.json`。

### Worker、对象存储和控制面

- 新增长期运行的 `radar-qc-basic` Worker 和
  `rainpulse.jobs.requested.radar_qc` NATS 路由。
- 新增迁移 `0007_radar_qc.sql`、`radar_qc_metrics` 表、确定性任务/事件 ID、
  事务内配置登记和终态幂等消费。
- QC 任务只有在归一化 URI 存在且健康状态不是 `UNAVAILABLE/UNKNOWN` 时才能
  创建。
- QC 阶段失败后允许使用新 pipeline version 重试；旧失败任务、attempt、inbox

- QC 对象前缀包含 `qc_pipeline_version`：


- 新增 `/api/v1/radar-scans/{scan_id}/qc-summary`，单站状态接口同步返回最新
  QI 与 QC 指标。

## 真实联调问题闭环

### 配置外键

首次创建 QC job 时触发 `jobs_config_version_fkey`。根因是 QC 配置版本尚未写入
全局 `config_versions`。修复为在同一事务中先登记规范化配置和 SHA-256，并验证
同版本不能对应不同内容，再创建 job/outbox。已检查其它 job 创建路径，真实解码
路径和模拟配置没有同类遗漏。

### 无 DBZH 仰角层

首次真实算法运行在 `group["DBZH"]` 处失败。根因是算法错误假设每个 sweep
都有反射率，而真实 Z9598 的 11 层中只有 9 层含 DBZH。修复后缺 DBZH 层保留
几何并输出全 NaN/缺测标志。回归测试先复现 `KeyError`，再验证修复。

### 失败扫描不能重试

归一化产物已经有效，但 QC 失败将 scan 标记为 `FAILED`，旧状态机无法重新进入
QC。修复后只有同时满足“归一化 URI 仍存在、健康门控通过、使用新的 pipeline
version”才能创建重试事件；同一失败版本不能伪重试。

### 成功后残留 Worker 错误

早期成功重试达到 `QC_READY` 后仍保留 `WORKER_PROCESSING_ERROR`。根因是终态
更新没有恢复 RP-007 健康原因。修复后开始新重试时移除临时错误，完成时从
`radar_health_metrics` 恢复 `CONFIG_NOT_READY,SOURCE_TIME_MISMATCH`。

### 版本化任务复用旧对象标记

早期 QC 输出路径只包含 radar/scan。新算法版本读取到 1.0.1 的不可变
`_SUCCESS.json` 后，Worker 正确拒绝把旧 completion 当作新 job。修复为将
pipeline version 纳入对象前缀，并补充契约和回归测试。

### 部署时配置进程缓存

QC profile 在 Worker 启动时加载。只更新挂载文件、不重启 Worker 会造成请求版本
与进程内版本不一致。105 部署流程已调整为：同步配置后重启 `radar-qc-worker`，
等待健康检查通过，再触发新版本 QC。
