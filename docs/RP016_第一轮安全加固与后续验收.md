# RP-016 第一轮安全加固与后续验收

更新时间：2026-08-26

## 1. 目标

本轮不是把 RainPulse 宣布为业务系统，而是在现有 RP-015 工程闭环上优先修复两类可能污染后续 QPE 和短临预报的问题：

1. 已经被质控明确识别为非气象回波的格点，不能因为标量 QI 仍高于工程门槛而重新进入 Hybrid Scan 或多雷达拼图；
2. 光流估计不能把雷达覆盖边缘、山体阴影或缺测孔洞的人为强梯度当作真实回波运动。

同时统一产品表达：当前 `confidence` 是工程质量指数，不是预报正确概率；当前页面是工程验证环境，不是业务上线声明。

## 2. 本轮已完成的修改

### 2.1 严重质控标记的下游硬门控

Hybrid Scan 与多雷达拼图的 `reject_flags` 现在至少包含：

```text
MISSING
HARDWARE_ANOMALY
RADIAL_INTERFERENCE
GROUND_CLUTTER
SEA_CLUTTER
ANOMALOUS_PROPAGATION
BIOLOGICAL_ECHO
```

这些原因仍完整保留在不可变的极坐标 QCRadarVolume 中，便于诊断和复核；但一旦某个 gate 已被当前质控版本明确标记，就不能进入 Hybrid Scan、基础 QPE 和 pySTEPS 输入。

`LOW_SNR` 与 `LOW_QUALITY` 暂继续作为软质量因子处理，不在本轮全部硬删除。

配置加载器增加了最低安全集合校验，后续即使误删某个严重标记，启动或测试阶段也会失败，而不是静默降低门槛。

新增测试覆盖：

- 低仰角被标记为径向干扰时，Hybrid Scan 必须跳过该仰角并选择可用高仰角；
- 高 QI 但被标记为径向干扰的雷达，不得参与多雷达线性 Z 融合。

### 2.2 pySTEPS 缺测边界缓冲

pySTEPS-LK 运动估计新增以下处理：

```text
连续输入有效区求交
→ 对缺测边界和孔洞做 5 格内缩
→ 在临时运动估计副本中做最近有效值延拓
→ 只统计缓冲区内的安全特征
→ 特征不足时显式零运动回退
→ 原始有效掩膜仍独立平流，决定最终产品支持区
```

该处理只修改运动估计工作副本，不会把缺测改写为无降水，也不会扩大最终有效产品区。

当前工程参数：

```text
minimum_trackable_rain_pixels: 64
minimum_motion_features: 4
missing_buffer_pixels: 5
```

新增输出与诊断：

```text
motion_valid_mask
motion_feature_count
motion_valid_fraction
motion_fallback_used
motion_fallback_reason
missing_buffer_pixels
```

当前结构化回退原因包括：

```text
insufficient_trackable_rain
no_motion_valid_domain
insufficient_motion_features
```

### 2.3 “置信度”语义修正

现有 `confidence` 由输入 QI 平流、时效衰减和低质量惩罚构成，尚未经过历史可靠性校准。因此本轮明确记录：

```text
confidence_kind = technical_forecast_quality_index_not_calibrated_probability
```

ForecastOutput 合约和 React 页面均改为“技术质量（非概率）”，禁止将其解释为预报正确概率。

### 2.4 页面状态修正

短临页面从：

```text
Operational nowcast / RP-015
```

改为：

```text
工程验证 / RP-016
```

并提示当前产品用于工程回放与检验，业务可用性仍由上游质量门控和实况评分共同决定。

## 3. 本轮有意未处理的事项

以下事项缺少权威资料或需要真实连续过程，不能在代码评审中猜测完成。

### 3.1 RSTM 原始保留码语义

当前源数据代码 `0–4` 的正式含义仍需数据提供方或雷达厂商确认。未确认前，本轮不把它们擅自改成“无雨”或其他状态。

后续应冻结：

```text
OBSERVED_ECHO
OBSERVED_NO_ECHO
BELOW_THRESHOLD
RANGE_FOLDED
INVALID
NOT_SAMPLED
MISSING
```

并新增 `GATE_STATE`、`OBSERVABLE_MASK`、`METEO_VALID_MASK` 与 `MODEL_INPUT_MASK`。该项是恢复真实有效覆盖率、构建真实 NowcastInput 的首要前置条件。

### 3.2 真实连续序列和预报技巧

本轮仍不能证明 pySTEPS 在真实天气过程上有技巧。至少需要三帧连续、固定五分钟、上游业务门控通过的真实 RadarAnalysis，随后完成：

```text
持续性
整场平移
pySTEPS-LK
```

按时效、阈值、天气类型和 QI 分组的 CSI、POD、FAR、FSS 与累计降水检验。

### 3.3 质控专项资产

静态杂波图、海杂波/AP 概率图、权威高程基准、标定偏差和第二部雷达仍是正式业务门槛。本轮只保证明确标记的严重污染不会继续下传，不代表这些识别模块已经完成本地业务验收。

### 3.4 存储性能重构

当前 Worker 仍会把多对象 Zarr 完整读入内存并逐对象校验。该实现适合当前工程规模，但多雷达连续运行和历史回算前还需增加本地任务缓存、按块读取和请求量基准。

### 3.5 Go 模块路径和应用层拆分

Go module 仍保留历史路径，编排服务也仍较集中。本轮不把机械性重构与气象安全修改混在一个提交中，建议后续单独处理。

## 4. 兼容性说明

- ForecastOutput 仍使用合约 `1.1`；`motion_valid_mask` 和新的 motion 属性是可选增强，验证器仍可读取已提交的旧 RP-014 结果。
- 当前工程配置文件继续沿用既有 RP-014 标识，以避免在本轮同时迁移数据库、事件示例和已验收产品。正式业务冻结前应将本轮参数发布为新的不可变模型/配置版本，再进行一次完整回归和灰度部署。
- 已提交的历史验收记录不回写，不把本轮代码结果描述为已通过真实业务检验。
