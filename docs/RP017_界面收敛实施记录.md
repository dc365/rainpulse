# RP-017 界面收敛实施记录

## 目标

本轮只调整 React 信息架构与交互，不修改 MRMS 数据、pySTEPS-LK、评分算法、门禁结论或后端 API。

原算法验证页同时展开运行、案例、门禁矩阵、三组筛选、两条时间轴、三联地图、曲线、说明和完整表格，功能完整但视觉层级不清。RP-017 将页面重构为：

```text
先看结论
→ 统一选择案例和评分切片
→ 查看同一时效空间对比
→ 沿唯一预报时效轴浏览
→ 查看核心指标与曲线
→ 按需展开门槛、明细和溯源
```

## 已完成

### 1. 结论优先

页面顶部新增结论带，集中显示：

- 当前工程门槛结论；
- 完成/失败起报；
- 相对整场平移的代表性 FSS 差值；
- 运动回退次数；
- 空间地图证据数量；
- “MRMS 不等于福建业务验收”的明确边界。

### 2. 统一筛选

删除左侧运行/案例导航和独立起报时间轨道，统一为一条筛选区：

- 验证运行；
- 典型案例；
- 起报时间；
- 比较基线；
- 降水阈值；
- 高级设置中的 FSS 邻域。

技能门禁矩阵只展示冻结结论，不再与主筛选重复竞争。

### 3. 地图成为主体

三张地图继续共享视野、范围和色标，但：

- 标题与角色改为中文；
- 默认关闭参考底图，减少重复外部瓦片和视觉噪声；
- 地图高度提升至 380 px；
- 比例尺、图例和技术说明在整组地图层面收敛；
- 播放控制移到唯一的预报时效轴。

### 4. 证据分层

默认展示：

- 当前时效核心指标；
- FSS 逐时效曲线；
- 当前评分切片说明。

以下内容改为折叠区域：

- 冻结通过门槛；
- 完整指标表；
- 运行与数据溯源。

### 5. 可分享状态

当前 run、case、issue、lead、baseline、threshold 和 window 会写入 URL 查询参数。刷新页面或分享链接后，可以回到同一验证证据切片。

### 6. 请求一致性

切换运行、案例、阈值或邻域时，旧指标和旧地图立即清空并显示加载状态，避免短暂展示上一切片的数据。

### 7. 远程证据状态的局部 lint 约束

`AlgorithmVerificationWorkspace` 和 `VerificationMapMatrix` 在查询身份变化时会同步清空上一组远程证据，避免旧案例、旧时效或旧地图短暂留在页面。React Hooks 新版推荐规则会把这类显式状态边界视为 `set-state-in-effect`，因此仅对这两个文件设置局部例外；其他组件继续执行仓库级完整 Hooks 规则，未做全局放宽。

## 有意未修改

- MRMS 数据下载与状态语义；
- 10 分钟到 5 分钟因果重采样；
- pySTEPS-LK 算法；
- 持续性和整场平移基线；
- FSS/CSI/POD/FAR 计算；
- 工程门禁规则；
- Go API 和报告文件契约。

上述验证严谨化内容由下一步 RP-018 单独处理，避免界面重构与算法变更混在同一个 PR。

## 建议验收

```bash
make test-web
make lint
make build
make test
```

人工检查至少覆盖：

1. 桌面宽屏下结论、筛选、三联地图、时效轴和核心指标是否一屏形成主线；
2. 低于 1180 px 时三联地图是否切换为单图标签；
3. 低于 820 px 时筛选区和证据区是否改为单列；
4. URL 参数是否随选择同步；
5. 切换运行和案例时是否不会残留旧地图或旧评分；
6. MRMS 工程边界是否始终可见。
