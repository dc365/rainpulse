# RP-019 运行可靠性与自动化实施记录

更新时间：2026-08-29

## 1. 范围与结论

本轮补齐不依赖福建业务雷达资料即可完成的运行基础。实现仍以 v1.1
方案为准，质控严格位于拼图、QPE 和短临预报之前。本轮不宣称福建业务
可用：真实 gate 状态语义、权威站点/标定资料、静态杂波与海杂波/AP 资产、
第二部雷达、雨量站订正和连续天气过程评分仍是验收门槛。

本轮形成的自动链路为：

```text
稳定到达的雷达基数据
→ 探测 RSTM 内部 UTC 时间并计算 SHA-256
→ 不可变 raw 对象归档
→ 注册解码任务
→ 极坐标 QC
→ Hybrid Scan / 单雷达网格
→ 五分钟对齐的质量感知拼图
→ QPE 与诊断产品
→ 固定步长 NowcastInput
→ pySTEPS-LK
→ PNG / COG / NetCDF 应用产品
```

连续接入和自动计划器默认关闭。只有在雷达配置达到 `ready`、源目录和到达
规则确认、原始码语义冻结后，才可在测试环境显式启用。

## 2. 已实施内容

### 2.1 原始数据归档与连续接入

- 编排器读取 RSTM 径向头确定体扫起止 UTC，不依赖文件名猜测时间；
- 文件在两次扫描之间大小和修改时间均不变，且超过最小到达年龄后才处理；
- 探测、哈希期间若文件发生变化则拒绝注册；
- 原始字节先写入 `radar/raw/{radar_id}/.../{sha256}/...` 不可变对象，再创建
  解码工作流；数据库和 Worker 只引用归档后的 `s3://` URI；
- 相同内容通过稳定对象键和数据库确定性身份实现重启后幂等；
- 解码 Worker 不再需要 NAS 挂载，NAS 仅以只读方式挂载到编排器接入端。

原始 gate 整数码同时保存在规范化 Zarr 的 `<FIELD>_RAW_CODE` 数组中。
`0–4` 仍按当前安全规则不参与气象值计算，但不再丢失，待数据方确认后可在
不重新读取厂商格式的情况下回放语义映射。

### 2.2 持久状态驱动的自动计划

编排器可从 PostgreSQL 状态发现待处理对象，按阶段创建确定性任务。它使用：

- 明确的真实雷达 allowlist，避免合成数据进入业务计划；
- 固定网格身份，避免 MRMS 或其他验证网格混入福建产品；
- 一小时默认回看窗口，避免首次启用时意外回灌全部历史数据；
- 两分钟默认拼图等待时间，给同一五分钟时次的其他雷达到达留出窗口；
- 数据库唯一键、outbox/inbox 和对象提交标记实现进程重启后的恢复与去重。

关键开关：

```text
RAINPULSE_RADAR_INGEST_ENABLED=false
RAINPULSE_PIPELINE_ENABLED=false
RAINPULSE_PIPELINE_RADAR_IDS=z9598
```

启用前必须审查 `deploy/.env.example` 中的源目录、雷达配置、回看时间和各阶段
版本。单雷达工程回放可以生成降级分析，但不会绕过 NowcastInput 的业务质量
门槛。

测试环境按以下顺序启用与回退：

```text
1. 保持 PIPELINE=false，只启用 RADAR_INGEST，核对 raw 归档和解码注册
2. 确认雷达 allowlist、网格和全部配置版本后，再启用 PIPELINE
3. 观察 metrics、outbox 和阶段状态，不扩大 lookback 做历史回灌
4. 异常时先将两个开关改回 false 并重启 orchestrator
5. 不删除 PostgreSQL、JetStream 或 MinIO 数据；从失败状态和审计记录定位原因
```

### 2.3 Worker 重试和原子发布

- 长任务定期发送 ACK 进度，避免合法任务因超时被并发重复执行；
- 超时、连接错误、NATS 超时和选定的对象存储 5xx 采用指数退避重试；
- 默认最多投递三次，只有重试耗尽才发布终态失败；
- `job_attempts` 记录实际最终投递次数，完成诊断保留 worker、attempt 和上限；
- 制品数据写入内容寻址的 `_objects/{bundle_sha256}`，稳定 `_SUCCESS.json`
  使用条件写入，由首个提交者决定权威完成事件；
- Reader 同时兼容旧标记格式，逐对象校验大小和 SHA-256，并设置 100,000 个
  对象、默认 2 GiB 的内存安全上限。

当前仍是完整制品读入内存的工程实现。真实多雷达连续运行和历史回算前，需以
实际 Zarr 大小做峰值 RSS、对象请求数和阶段耗时基准，再决定分块读取和本地缓存。

### 2.4 控制面与基础设施安全

- `/api/v1/admin/*` 使用 Bearer token；未配置 token 时管理接口默认拒绝；
- 列表接口限制为每页 `1–200`，不再允许无界查询；
- 当前无法真实重建的 rerun 请求返回冲突，避免伪造“重跑成功”；
- API 默认只绑定环回地址，由 Web 网关作为唯一公开入口；
- Web 网关不转发 `/api/v1/admin/*`；管理调用只能通过测试机环回 API（例如
  SSH 隧道）访问，避免 token 经过公开的明文 Web 端口；
- API 和 Web 增加 CSP、禁止嗅探/嵌框、Referrer/Permissions 等响应头；
- NATS 开启用户名密码认证；
- MinIO Worker 从内置 `readwrite` 改为仅允许项目 bucket 指定前缀的
  List/Get/Put，且不授予删除权限；
- 项目 bucket 启用对象版本控制；条件写入负责正常路径的不可变性，版本历史
  为误覆盖再提供一层可恢复保护；
- 管理 token、NATS、PostgreSQL 和 MinIO 密钥只存在未跟踪的部署环境文件中。

内置 MinIO 策略以固定 bucket `rainpulse` 为边界。若未来需要多 bucket，应先为
各服务拆分独立身份和策略，不应仅修改 bucket 名绕过策略设计。

### 2.5 可观测性和构建追踪

- Go 构建注入 Git revision，API、Web 和编排器暴露一致的构建身份；
- API `/metrics` 与编排器健康端口 `/metrics` 输出任务、雷达扫描、分析、预报、
  outbox 状态，以及最新雷达延迟和最老待处理任务年龄；
- Compose 增加固定版本 Prometheus，默认仅绑定环回地址；
- 工程告警覆盖控制面不可用、雷达数据超过 10 分钟、任务超过 10 分钟和
  outbox 失败。

上述 10 分钟阈值是测试期工程值，不是正式业务 SLA。真实到达频率和连续运行
测量完成后，需要按天气业务要求冻结可用性、端到端延迟和误报抑制规则。
当前只加载 Prometheus 规则并在其界面显示告警，尚未配置 Alertmanager、短信、
邮件或即时通信通知；通知目标和升级责任人确认后再接入，不能把“规则存在”解释
为“已经有人收到通知”。

## 3. 保留与容量边界

当前自动生效的边界：

| 数据 | 当前边界 | 说明 |
|---|---:|---|
| NATS JetStream | 单 stream 7 天 / 1 GiB；全局文件存储 20 GiB | 丢弃最旧事件，数据库仍保存工作流审计 |
| Prometheus | 15 天 / 5 GB | 先达到的时间或容量边界生效 |
| 单个输入制品 | 默认最多 2 GiB | 防止 Worker 一次性读入超大制品 |
| 原始雷达、Zarr、产品 | 暂不自动删除 | 原始数据不可变；删除规则必须先冻结业务保留期和恢复要求 |
| PostgreSQL 业务记录 | 暂不自动删除 | 工作流、输入和版本追踪是可审计链的一部分 |

没有明确保留策略前，不增加会删除 MinIO 或 PostgreSQL 数据的定时任务。连续
接入前应先统计单体扫字节数、日体扫数、各阶段膨胀倍数和磁盘水位，再冻结
raw/中间制品/应用产品的差异化保留期与低水位告警。
对象版本控制也会占用容量，容量审计必须同时统计非当前版本。

## 4. 本轮验证

本地验收至少运行：

```bash
make test
make lint
make build
```

部署测试环境后还需检查：

```text
Compose 所有服务健康
Web/API/Prometheus 仅暴露预期端口
API 与编排器 build identity 一致
未配置 token 时管理 API 拒绝访问
NATS 匿名连接失败、服务连接成功
MinIO Worker 身份不能删除对象或访问非授权前缀
Prometheus targets 与规则加载成功
旧的已发布产品仍可由兼容 Reader/API 读取
```

## 5. 福建真实数据到位后的顺序

1. 冻结站点、硬件、标定、垂直基准、RSTM 保留码和文件到达语义；
2. 以晴空和典型天气样本生成并人工复核静态杂波图、海杂波/AP 资产；
3. 将雷达配置从 `draft` 升为 `ready`，先开启归档接入，核对不可变对象与时次；
4. 只开单阶段自动计划，连续观察 decode/QC/grid，再逐步开放 mosaic/QPE；
5. 获得至少三帧连续五分钟的合格 RadarAnalysis 后开放 NowcastInput 和 LK；
6. 以持续性、整场平移为基线完成分天气、分阈值、分时效检验；
7. 第二部雷达和质控雨量站到位后，分别验收多雷达拼图和雨量订正；
8. 完成性能压测、故障注入和至少 7 天连续运行后，才评审业务上线。
