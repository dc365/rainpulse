# RP-027：离线模型对比工作台实施记录

## 1. 目标

把 RP-026 已冻结的 MRMS 概率集合验证结果接入现有 Web 算法验证工作台，形成可读、可追溯的模型对比闭环，同时保持以下边界不变：

- STEPS 继续是主概率基线；
- NowcastNet 只作为离线候选；
- 原始集合概率仍未校准；
- 实时影子、产品发布和福建业务资格保持关闭；
- 不把 MRMS 结果解释为福建原始雷达质控、QPE 或业务验收证据。

## 2. 控制面契约

算法验证运行增加 `verification_kind`：

- `deterministic_spatial`：现有 RP-016/RP-018 FSS、地图和逐时效明细；
- `probabilistic_ensemble`：RP-026 概率集合汇总。

概率集合详情只暴露冻结汇总中的必要证据：

- 近时效 10 至 60 分钟和远时效 70 至 120 分钟；
- NowcastNet、STEPS、LK、持续性、相位相关的 CRPS、集合均值 RMSE 和集合离散度；
- NowcastNet 相对各基线的 CRPS 技巧和分阈值 Brier 技巧；
- 最低共同验证覆盖率和集合成员覆盖率；
- NowcastNet/STEPS/完整流程运行时间及 GPU、RSS 峰值；
- 数据切分、校准状态、成员数、设备和产品发布开关。

控制面从只读报告目录读取汇总。概率报告若开启 `operational_eligible` 或 `product_publication_enabled`，会被判为非法报告，不进入工作台。

## 3. Web 工作台

概率集合运行不复用确定性 FSS 的案例、邻域、地图和逐时效接口，避免生成不存在的空间证据。页面按以下顺序展示：

1. 结论和上线边界；
2. 近、远时效五模型对比；
3. 1/5/10/20/50 mm/h Brier 技巧矩阵；
4. GPU 与完整流程资源统计；
5. 可展开的运行溯源。

桌面端保留同列对齐的模型表格；窄屏使用横向滚动，避免把同一指标拆成无法比较的卡片。原有确定性验证视图和 GIS 地图流程不变。

## 4. 报告发布方式

完整 RP-026 回算目录继续保存在服务器原位置。控制面只需要一个扁平的只读汇总入口，可使用：

```bash
scripts/stage_probabilistic_verification_summary.sh \
  /data/Weather/RADA/RADA_MRMS/reports/rp026-mrms-nowcastnet-v1/holdout/holdout-v1/summary.json \
  /data/Weather/RADA/RADA_MRMS/reports \
  holdout-v1
```

脚本先检查离线边界，再以原子替换方式写入：

`/data/Weather/RADA/RADA_MRMS/reports/rp026-mrms-nowcastnet-v1/holdout-v1/summary.json`

这只是控制面展示副本，不修改原始回算目录和任何评分结果。

## 5. 当前结论

独立留出集 50/50 起报完成且 0 失败。近时效 NowcastNet 相对持续性、LK、相位相关的 CRPS 技巧分别为 `+20.17%`、`+14.09%`、`+19.25%`，相对 STEPS 为 `-36.61%`。因此工作台明确显示“STEPS 保持主基线，NowcastNet 保留为离线候选”。

## 6. 下一步

福建真实雷达数据到位前，不继续用已花费的 MRMS 月份调参。可继续做控制面可靠性和可观测性；福建连续 QC/QPE 序列到位后，回到 v1.1 的质控优先主线，再开展本地校准、迁移学习和独立留出验收。
