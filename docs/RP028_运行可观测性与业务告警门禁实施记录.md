# RP-028：运行可观测性与业务告警门禁实施记录

## 1. 目标

在福建实时雷达数据到位前，补齐 v1.1 第 19 节中不依赖业务样本的运行指标与告警链路，同时保证工程回放不会被误报为业务运行事件。

本轮不启用连续 ingest、自动 planner、NowcastNet、概率校准或产品发布，也不改变任何已冻结 MRMS 结论。

## 2. Prometheus 指标

API 和 orchestrator 的 `/metrics` 继续从 PostgreSQL 只读生成快照，新增：

| 指标 | 定义 |
|---|---|
| `rainpulse_radar_scan_received_total` | 已登记的不可变雷达体扫总数 |
| `rainpulse_radar_decode_failed_total` | 状态为失败的雷达解码任务总数 |
| `rainpulse_radar_latest_scan_available` | 每部已配置雷达是否存在最新体扫证据 |
| `rainpulse_radar_scan_completeness` | 每部雷达最新体扫完整率 |
| `rainpulse_radar_data_delay_seconds` | 每部雷达最新体扫结束时间距当前时间 |
| `rainpulse_radar_qc_duration_seconds` | 每部雷达最近一次成功极坐标质控耗时 |
| `rainpulse_radar_qi_mean` | 每部雷达最新平均质量指数 |
| `rainpulse_radar_interference_ratio` | 径向干扰射线数占实际径向数比例 |
| `rainpulse_radar_clutter_ratio` | 地物、海杂波和 AP 标记占有效加缺测距离库比例 |
| `rainpulse_radar_blockage_ratio` | 波束遮挡缺测格点占目标网格比例 |
| `rainpulse_radar_missing_ratio` | 缺测格点占目标网格比例 |
| `rainpulse_analysis_radar_count` | 最新完成分析的实际贡献雷达数 |
| `rainpulse_analysis_valid_coverage_ratio` | 最新完成分析的有效覆盖率 |
| `rainpulse_analysis_publish_delay_seconds` | 分析时次到 QPE 完成证据时间的延迟 |
| `rainpulse_qpe_station_bias` | 雨量站订正启用后的偏差，占位指标当前不输出样本 |

雷达指标携带 `radar_id` 和 `lifecycle`；分析指标携带 `operational_eligible`。没有对应制品时不伪造质量值为零。最新体扫是否存在使用独立的 0/1 指标表达，使 `ready` 雷达完全无数据时仍可明确告警。

## 3. 工程告警与 fail-closed 边界

新增或收紧的工程规则：

- `ready` 雷达完全没有体扫证据，持续 2 分钟后 critical；
- `ready` 雷达数据延迟超过 10 分钟，持续 10 分钟后 warning；
- `ready` 雷达体扫完整率低于 97%，持续 10 分钟后 warning；
- `ready` 雷达平均 QI 低于 50%，持续 10 分钟后 warning；
- `ready` 雷达径向干扰比例超过 2%，持续 5 分钟后 warning；
- `operational_eligible=true` 的分析覆盖低于 50%，持续 10 分钟后 critical；
- `operational_eligible=true` 的分析发布延迟超过 10 分钟，持续 5 分钟后 warning。

这些阈值仍是工程默认值，不是福建业务 SLA。雷达配置为 `draft` 或 `disabled`、分析不可业务发布时，Prometheus 仍保留工程指标，但业务告警规则不匹配这些样本。

告警当前只加载到 Prometheus，尚未接入 Alertmanager、短信、邮件或即时通信。未配置通知责任人前，不把规则存在解释成已完成值守闭环。

## 4. Web 运行门禁

雷达运行详情新增一条紧凑的业务告警门禁：

- 显示数据时效、完整率、平均 QI 和径向干扰比例；
- `draft` / `disabled` 明确显示“业务告警已抑制”，当前越界只作为工程证据；
- `ready` 显示“业务告警已启用”及越界项数；
- `ready` 且缺少体扫、健康或质控证据时按越界处理，不显示为正常。

页面不替代 Prometheus 规则状态，也不提供告警确认或静默操作，避免形成尚未实现的值守承诺。

## 5. 验证

本地门禁：

```bash
make contracts-check test-go test-web
pnpm --dir apps/web lint
pnpm --filter @rainpulse/web build
```

部署后验证：

```bash
curl -fsS http://127.0.0.1:8080/metrics
docker compose --env-file deploy/.env -f deploy/docker-compose.yaml exec -T prometheus \
  promtool check rules /etc/prometheus/rainpulse-alerts.yaml
```

还需检查 Prometheus targets、当前 firing 规则，以及桌面和 375px 雷达运行页无横向溢出。

## 6. 下一步

福建实时数据到位前，可继续补齐值守闭环中不依赖业务阈值的部分：Alertmanager 接入占位配置、告警状态只读 API、失败任务和 outbox 的关联追踪、磁盘与对象存储容量指标。外部通知目标、正式 SLA、静默和升级策略必须由业务责任人确认后才能启用。
