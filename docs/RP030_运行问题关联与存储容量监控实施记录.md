# RP-030：运行问题关联与存储容量监控实施记录

## 1. 目标与边界

本轮继续补齐 v1.1 第 19 节的值守证据，但不依赖福建实时雷达数据：

- 让阻塞任务、近期失败任务和滞留 Outbox 告警定位到具体记录；
- 在控制 API 和 Web 中只读展示失败原因、尝试次数和关联标识；
- 采集 105 主机根文件系统与 MinIO 可用容量；
- 保持 Alertmanager 本地 receiver，不启用外部通知和处置操作。

本轮不新增数据库表，不改变任务重试、Outbox 发布或对象清理语义，也不把工程阈值解释为正式 SLA。

## 2. 可关联运行指标

控制面从现有 `jobs`、`job_attempts` 和 `outbox_events` 生成以下指标：

| 指标 | 说明 |
|---|---|
| `rainpulse_job_active_seconds` | 每个 `PENDING/RUNNING` 任务的持续时间，保留 `job_id/run_id/job_type/status` |
| `rainpulse_job_failure_timestamp_seconds` | 最近 24 小时失败任务的终止时间，保留任务标识和 `error_code` |
| `rainpulse_outbox_event_pending_seconds` | 每个未发布 Outbox 的存续时间，保留 `event_id/aggregate_id/event_type/subject` |

每类明细最多输出 200 条，错误消息不进入 Prometheus 标签。失败消息只通过内部只读 API 返回，并截断为 500 个字符，避免无界响应和高基数标签。

告警规则调整为：

- 单个任务持续超过 10 分钟，持续判定 5 分钟后 critical；
- 任务失败后 30 分钟内形成 warning，保留具体任务标识，随后自动恢复；
- 单个 Outbox 超过 1 分钟未发布，持续判定 2 分钟后 warning；
- 原有全局 `jobs/outbox` 状态计数继续保留用于趋势，不再作为无法定位的主告警。

## 3. 存储容量指标

- node-exporter 固定为 `v1.9.1`，无宿主机端口，只读挂载 `/` 并由 Prometheus 在 Compose 网络内采集；
- MinIO 设置 `MINIO_PROMETHEUS_AUTH_TYPE=public`，但 MinIO 宿主机端口仍只绑定 loopback，指标仅供内部 Prometheus 使用；
- 主机根文件系统和 MinIO 可用容量低于 15% 持续 10 分钟后 warning，低于 5% 持续 2 分钟后 critical；
- 任一存储指标目标不可采集持续 2 分钟后 warning。

这些阈值是工程保护线。正式留存周期、清理策略和容量扩容线需要结合福建体扫字节数、日体扫量、网格与集合膨胀倍数后冻结。

## 4. 只读 API 与 Web

新增：

```text
GET /api/v1/operations/issues
```

API 返回：

- 失败任务、阻塞任务和滞留 Outbox 计数；
- `job_id`、`run_id`、`event_id`、`aggregate_id`；
- 任务或事件类型、当前状态、尝试次数、持续时间；
- 有界错误码和错误消息、创建与更新时间。

告警中心新增“关联运行问题”扁平台账。前端按告警标签中的标识和运行证据做精确关联，显示“已关联告警中/待生效/已抑制”；没有活动规则时明确显示“尚未进入活动告警”，不伪造处置状态。

## 5. 验证

本地门禁：

```bash
make contracts-check test-operations test-alerting test-go test-web
make lint
pnpm --filter @rainpulse/web build
```

部署后验证：

```bash
docker compose --env-file deploy/.env -f deploy/docker-compose.yaml config --quiet
docker compose --env-file deploy/.env -f deploy/docker-compose.yaml exec -T prometheus \
  promtool check rules /etc/prometheus/rainpulse-alerts.yaml
curl -fsS http://127.0.0.1:8080/api/v1/operations/issues
curl -fsS http://127.0.0.1:9090/api/v1/targets
```

还需确认 `minio` 和 `node-exporter` target 为 up，容量指标非空，以及桌面和 375px 告警中心无横向溢出或控制台错误。
