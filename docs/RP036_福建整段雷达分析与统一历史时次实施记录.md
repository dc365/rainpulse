- 已发布或已检验的未来预报；
- 已完成基础质控、四站对齐、质量感知拼图和 QPE 的历史雷达分析。

分析仍保留在诊断和 API 中，但不伪装成多雷达产品。连同原有 2026-08-25 预报，当前
历史选择器共提供 85 个可选项。

这些是历史雷达 QPE 分析，不是未来短临预报。所有福建分析仍为工程配置、均未通过
业务预报输入门禁。本轮明确关闭预报规划，00:00–10:40 UTC 范围内新增 forecast run
数为 0。

“实际贡献站数”是拼图质量衰减和格点选择后的结果，并不表示少于四站输入。原始体扫

序列；没有四站同步输入的时间桶会按设计跳过。

`operational_eligible=false`，雨量站订正均保持关闭。最大雨强达到冻结的 300 mm/h
上限，需要后续结合标定资料、静态杂波图和代表性强对流个例复核，不能作为业务质量
已通过的证据。

## 批处理与规划器调整

新增可复用命令：

```bash
orchestrator radar-batch-ingest \
  /opt/rainpulse/configs/radars/fujian-20260828 \
  /data/Weather/RADA/RADA_L2_FMT/OBS_TEMP/2026/20260828
```

该命令读取雷达 YAML、发现对应站目录、校验文件、归档不可变原始数据并走正常解码
任务。发现结果按文件时间再按雷达排序；后续新批次可边处理边形成跨站时次，而不是先
排完一个站再处理下一个站。

历史规划器增加两项显式门控：

- `RAINPULSE_PIPELINE_FORECAST_ENABLED=false`：只运行到 QPE/诊断，不创建预报；
- `RAINPULSE_PIPELINE_REQUIRE_ALL_RADARS=true`：只有四站扫描都已到统一网格且落入同一
  分析桶，才允许创建拼图任务。

规划器的雷达扫描读取改为每页 200 条、持续分页到完整结果集。此前全站共用的 200 条
上限只能覆盖 04:35 UTC 之后的 51 个分析时次；分页修复后补齐到 00:10 UTC，最终为
87 个。实时部署默认仍保持 ingest 和 pipeline 关闭，以上历史参数只用于受控回放。

## 界面行为

没有新增页面或导航项。原有短临页完成以下调整：

1. “实时”仍只跟随已发布预报；“历史时次”合并预报和多雷达分析目录。
2. 每项以“分析”或“预报”明确标识，并同时显示 CST 与 UTC。

   提示“非未来预报、未通过业务预报输入门控”。

## 仍然关闭的业务能力

本轮扩大的是“真实雷达分析可回放范围”，不是放宽业务门禁。以下事项仍未完成：

1. 至少两站权威台站/高程基准、标定信息和 `ready` 配置验收；
2. 静态杂波图、海杂波/AP 概率、山地遮挡代表性个例和业务确认的 QC 阈值；
3. 雨量站观测、质量规则和 QPE 标定/订正；
4. 连续合格的 NowcastInput、真实福建未来预报及技巧检验。

只有这些门禁通过后，福建分析才能进入 NowcastInput 和 0–2 小时预报链。
