## 时效项与数据质量项

拼图权重拆为两层：

1. `source_quality` 来自上游雷达解码、极坐标质控、Hybrid Scan 和单站网格，是判断数据本身质量的主项。
2. `time_quality` 只表达雷达体扫结束时间与五分钟分析时次之间的轻微不同步，是次级修正项。

RP-039 的历史拼图配置将允许偏移从 150 秒放宽到 300 秒，并把时间质量下限设为 0.80：

```text
time_quality = 0.80 + 0.20 × max(0, 1 - abs(offset_seconds) / 300)
adjusted_quality = source_quality × time_quality
```

因此，-145 秒对应的 `time_quality` 约为 0.903，只对源质量折减约 9.7%，不会喧宾夺主。数据自身的质控标志仍可直接拒绝格点，拼图的最小质量、同质量线性 Z 融合和质量幂次权重也继续生效。放宽的是体扫时间匹配，不是雷达质控。

## 历史回算逻辑

历史与实时使用同一个产品语义：选中的时间点是起报时次 T0，实况雷达 QPE 是 T0 分析，LK 和 STEPS 是由 T0 之前的连续分析帧推理得到的 T+5 至 T+120 分钟预报。界面不增加页面或入口，仍在统一时间选择框、统一产品栏和统一有效时间轴中切换。

回算不是对每个孤立实况点强行生成结果。每个起报时次至少需要 3 帧连续的五分钟输入；断档、覆盖或质量不足时，时间点仍可查看实况，但 LK/STEPS 明确显示不可用。这样避免把不连续资料补零后伪装成模型预报。

历史回放配置 `rp039-historical-replay-v1`：

- 输入 3–6 帧，五分钟步长，选择以 T0 结束的最新连续序列；
- 工程门槛为有效覆盖率不低于 0.30、平均质量指数不低于 0.10；
- 不要求 draft 雷达帧具备业务运行资格，但保留全部缺测掩码和非业务原因；
- 对每个符合条件的历史起报时次建立独立 `NowcastInput`、运行、作业和产品工件。

2026-08-28 雷达历史序列加已有 2026-08-25 工程样例共筛出 38 个可回算起报时次。LK 的 38 个时次均已完成 24 个五分钟预报步长并发布应用产品；最晚可回算时次为 2026-08-28 10:20 UTC。10:30 UTC 虽然是四站代表性拼图，但 10:25 UTC 分析帧缺失，因此正确地只保留实况，不伪造预报。

STEPS 使用 `rp039-pysteps-steps-history-v4`：12 成员、AR(1)、参数化降水噪声、BPS 速度扰动，继续输出五档超阈概率和 P10/P50/P90。稀疏雷达有效域在工作副本中按干区下限参与数值计算，最终输出支持域仍与确定性有效域相交，原始缺测不会变成有效降水。

## 缺陷修复与回归保护

本阶段定位并修复了两个历史重算特有问题：

1. 拼图、QPE 和 NowcastInput 原工件前缀未包含 `analysis_id` 或 `run_id`，同一时次重新分析可能撞上旧 `_SUCCESS` 标记。三个前缀均已加入不可变工作流身份，并以重复时次回放回归测试保护。
2. STEPS 历史产品用 `mkdtemp` 原子发布，最终目录继承 0700，导致不同 UID 的只读 API 容器无法读取。发布前现显式设置 0755，并增加“不同运行 UID 可读”回归测试。

同时扫查了同类工件发布路径：验证地图发布器已经显式修正临时目录权限；本次历史 STEPS 脚本是遗漏点。算法层对非参数噪声非有限值和 AR(2) 奇异矩阵的真实雷达失败也已转为冻结的稀疏域稳定配置，并用真实 pySTEPS 后端测试覆盖。
