# RP-041 福建实时影子链路与统一工作台实施记录

## 1. 目标

本变更将 RainPulse 从“多个工程页面 + 单雷达轮询 + 固定延迟拼图”收敛为本周可验收的福建四站实时影子闭环：

```text
四站到报
→ 不可变原始归档
→ 解码
→ RP-040 径向干扰质控
→ Hybrid Scan
→ 四站水位线拼图
→ QPE
→ pySTEPS-LK
→ 一个周期 / 一个时间轴 / 多幅同步地图
```

系统仍未业务化。本阶段所有福建实时结果均为 `realtime_shadow`，不得据此把 draft 雷达配置提升为 ready，也不得将 NowcastNet 结果作为业务产品发布。

## 2. 四站实时接入

新增独立 `rainpulse-ingest` 进程和严格 JSON manifest：

- 一份清单声明 Z9591、Z9593、Z9598、Z9599；
- 每站独立扫描状态和失败统计；
- 文件大小、修改时间连续两次不变后才读取；
- 原始字节先写入内容寻址的 MinIO 归档，再登记解码工作流；
- 扫描账本原子持久化，进程重启不会重复发现已成功登记文件；
- 共享日期目录通过站号过滤，文件名必须含配置站号；
- 业务模式要求 ready 雷达，影子模式允许 draft 配置但保留非业务标识。

接入状态通过进程 `/status` 暴露，并由控制 API 的 `/api/v1/workspace/ingest-status` 只读转发给后台。

## 3. 拼图水位线

原逻辑在 `analysis_time + 固定延迟` 只生成一次拼图，晚到雷达会永久错过该时次。新逻辑使用两条水位线：

1. 四站全部格点化完成，并超过最短 30 秒等待：立即生成；
2. 未到齐但超过 4 分钟最大等待，且至少有 2 站：生成明确降级拼图。

`RAINPULSE_PIPELINE_REQUIRE_ALL_RADARS=true` 时禁止超时降级。每次越过水位线都会记录贡献站数、预期站数、是否完整和触发原因。

## 4. 实时影子模式

新增顶层 `RAINPULSE_PIPELINE_MODE=operational|realtime_shadow`。部署覆盖文件固定四站 allowlist、RP-040 QC/格点配置和 RP-041 拼图配置。

现有 NowcastInput 1.2 事件只定义 `operational` 与 `historical_replay` 两个传输值。RP-041 暂将后者作为“任何非业务输入”的 fail-closed 传输枚举，外层流水线和 Web 均明确标识为 `realtime_shadow`。它不能被 operational 模式接受，也不会获得业务资格。后续升级 NowcastInput 合约时应删除这一兼容映射，而不是继续扩散旧名称。

## 5. 统一 Workspace API

新增三个只读接口：

```text
GET /api/v1/workspace/cycles
GET /api/v1/workspace/cycles/{cycle_id}
GET /api/v1/workspace/ingest-status
GET /api/v1/workspace/nowcastnet-shadow-status
```

Workspace 投影在同一 Go 进程内组合已有 run、analysis、diagnostic、product、ensemble API，不绕过原控制面，也不直接访问数据库或对象存储。周期详情返回：

- 周期、时效与新鲜度；
- 参与雷达和时间偏差；
- 覆盖率、平均 QI、最大雨强；
- 绝对有效时间轴；
- 选定起报后未来两小时雷达分析自动作为检验实况帧；
- 固定 QPE/LK/STEPS/NowcastNet 面板；
- 原始/QC/QC flags 等诊断面板；
- 明确的不可用原因。

## 6. Web 收敛

顶层业务导航被移除，仅保留：

- `/` 主工作台；
- `/admin` 后台。

主工作台具有：

- 实时跟随 / 历史固定；
- 30 秒自动刷新；
- 预报对比、质控排查、检验回放三个预设；
- 一个周期选择器；
- 一个按绝对 `valid_time` 驱动的时间轴；
- 一至四幅共享 OpenLayers View 的同步地图；
- 移动端单图标签切换；
- 模型原生帧缺失时明确提示，不插值、不串用其他模型结果。

后台合并数据源、雷达处理状态、运行问题与告警证据，不提供在线调参，以版本化配置为唯一运行依据。

## 7. NowcastNet 福建影子门禁

新增独立于 RP-026 的福建影子输入探测模块和 profile，保留官方 MRMS 权重父身份：

- 精确选取 `T-80 ... T0` 的 9 个 10 分钟帧；
- 从 5 分钟序列选帧，不做时间插值；
- 固定原生 0.01° ROI，不随天气移动；
- 任意输入帧或 ROI 格点缺测即拒绝；
- 不把缺测转换为零雨量；
- 固定 `192 × 480` 候选尺寸在 GPU 验证前保持 `inference_enabled=false`；
- 独立探测服务每 30 秒检查最新完整 9 帧，并向 Workspace/Admin 返回具体门禁状态；
- 探测服务仅读取已提交 RadarAnalysis，不执行未验证的官方模型；
- 输出只规划 +10 至 +120 分钟；
- 业务发布和 operational eligibility 始终关闭。

本变更提供输入/ROI probe，不伪造已通过 GPU 形状验收的结论。官方权重空间尺寸探测命令为：

```bash
PYTHONPATH=algorithms python scripts/nowcastnet_fujian_shape_probe.py \
  --parent-profile configs/nowcast/rp026-nowcastnet-offline-v1.yaml \
  --capsule-root /opt/rainpulse/nowcastnet/official-v1 \
  --height 192 --width 480 --members 1 \
  --output runtime/evidence/fujian-nowcastnet-shape-192x480.json
```

只有该证据通过且独立真实输入验证完成后，才能新建下一版 profile 将
`spatial_shape_validated` 置为 true；不得原地改写已提交版本。

## 8. 部署

构建：

```bash
scripts/build_realtime_shadow.sh
```

启动：

```bash
docker compose \
  --env-file deploy/.env \
  -f deploy/docker-compose.yaml \
  -f deploy/docker-compose.realtime-shadow.yaml \
  up -d --build
```

部署覆盖文件增加独立接入进程和 NowcastNet 输入探测进程，关闭 orchestrator 内旧的单源 watcher，并启用四站实时影子 planner。

## 9. 验收口径

至少验证：

1. 四站新文件可持续登记，服务重启不重放已登记文件；
2. 文件写入中不会被读取；
3. 四站到齐后提前拼图，缺站时等待至最大水位线；
4. 至少 3 个连续 5 分钟有雨时次到达 QPE 和 LK；
5. 原始/QC/标记/QPE 可在一个周期和时间轴中同步排查；
6. LK 失败不被 NowcastNet 阻塞；
7. NowcastNet 输入不满足时返回具体原因，绝不补零或插值；
8. 主界面和后台在桌面与移动端均无页面级横向溢出。
