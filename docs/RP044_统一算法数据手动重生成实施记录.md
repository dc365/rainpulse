# RP-044 统一算法数据手动重生成实施记录

更新日期：2026-09-02

## 1. 目标

为算法调整后的福建历史样例提供一个简洁、受控的重生成入口，覆盖：

- 主控制链路：NowcastInput → pySTEPS-LK → 应用产品；
- 离线对比链路：pySTEPS-STEPS；
- 公开权重影子链路：NowcastNet。

本次不增加新的服务、任务表或任意参数执行接口。Web 网关继续阻断
`/api/v1/admin/*`，操作员只在服务器本机通过 Make 命令调用已有管理接口或受控脚本。

## 2. 收敛后的操作入口

统一入口为：

```bash
make regenerate REGEN_PRESET=<preset> ...
```

支持的操作预设：

| 预设 | 作用 | 必填输入 |
|---|---|---|
| `forecast-all` | 主链路、STEPS、NowcastNet | 下述三类输入的并集 |
| `pysteps-lk` | 从已提交的源运行重建 NowcastInput，并继续调度 LK 与产品 | `REGEN_RUN_ID`、管理令牌 |
| `products` | 安全重走主链路依赖并生成产品，不原地覆盖已发布任务 | `REGEN_RUN_ID`、管理令牌 |
| `pysteps-steps` | 从指定的已提交 NowcastInput 强制重建 STEPS | `REGEN_INPUT_URI`、`REGEN_ISSUE_TIME` |
| `nowcastnet` | 对指定完整历史周期重新运行公开权重 NowcastNet | `REGEN_ISSUE_TIME` |

示例：

```bash
RAINPULSE_ADMIN_TOKEN='***' make regenerate \
  REGEN_PRESET=pysteps-lk \
  REGEN_RUN_ID=<source-run-uuid> \
  REGEN_REASON='验证更新后的光流参数'

make regenerate \
  REGEN_PRESET=pysteps-steps \
  REGEN_INPUT_URI=s3://rainpulse/nowcast-input/.../input.zarr \
  REGEN_ISSUE_TIME=2026-08-28T02:30:00Z

make regenerate \
  REGEN_PRESET=nowcastnet \
  REGEN_ISSUE_TIME=2026-08-28T02:30:00Z
```

管理令牌不写入命令输出。公开的 4173 Web 仍为只读工作台，避免浏览器直接拥有数据重建权限。

## 3. 主链路控制面

沿用 `POST /api/v1/admin/runs/{run_id}/rerun`，仅扩展一个严格 JSON 请求：

```json
{
  "preset": "forecast_all",
  "reason": "验证更新后的算法配置"
}
```

控制面只接受固定预设和 3～240 字符的原因，不接受配置路径、Shell 参数或 Python
表达式。一次请求执行以下预检：

1. 源运行存在并含有成功提交的 NowcastInput；
2. 配置、网格、执行模式和固定 5 分钟序列与已提交谱系一致；
3. 至少存在 3 帧精确的源分析；
4. 同一源运行和同一预设没有仍在执行的重生成。

通过后创建新的可追溯运行，写入 `rerun_of` 和
`manual-regeneration/<preset>: <reason>`。新运行复用源运行已经提交的分析帧，生成新的
NowcastInput、LK 和应用产品，不由 Go 进程临时拉起 Python。

历史重生成带有 `rerun_of`，调度器仅对这类明确请求豁免实时 lookback；普通历史运行仍不会被
实时调度器误处理。工作台在同一格点、同一时次存在多个运行时只选择 `created_at` 最新的已发布
运行，因此用户只看到当前版本。

## 4. STEPS 与 NowcastNet

STEPS 脚本新增直接 `--input-uri`、`--issue-time` 和 `--force`，无需先制作临时目录清单。
强制重生成使用新的运行身份和对象前缀，发布采用“临时目录 → 校验完成 → 原子发布”；
新 bundle 成功后才删除同一格点、同一时次且契约身份匹配的旧 STEPS 目录，避免跨存储替换
中途失败时破坏当前可用产品。

NowcastNet 继续使用既有公开权重、完整九帧输入和拼接门禁。指定时次生成成功后，既有
`prune_cycle_versions` 只保留该格点、该时次最新的 bundle；若新结果未通过拼接门禁，则保留
原有可用产品，不用失败结果覆盖。

## 5. 版本与空间策略

- 工作台每个周期、每种算法只暴露最新成功版本；
- STEPS 与 NowcastNet 文件产品在成功发布后立即清除同周期旧 bundle；
- 主控制链路使用新的运行身份保证发布原子性，旧运行的数据库记录保留用于审计；
- 主链路对象仍遵循现有 MinIO 派生数据生命周期，不删除 raw 或 normalized 雷达输入；
- 重生成失败时不删除当前可用产品。

这里的“一个版本”指业务可见和离线文件产品只有一个当前版本；必要的运行、任务和输入谱系元数据
继续保留，避免无法解释某次结果来自何种输入与配置。

## 6. 验收

新增 `make test-regeneration`，覆盖：

- 管理接口请求契约、固定预设和原因校验；
- 重生成运行的新身份与 `rerun_of` 谱系；
- 同源同预设并发请求冲突；
- 历史运行的调度窗口豁免边界；
- 工作台同周期选择最新运行；
- STEPS 直接输入、强制新身份原子发布和同周期旧版本清理；
- 统一 Shell 入口语法和非法预设拒绝。

复现命令：

```bash
make test-regeneration
go test ./services/control/...
make contracts-check
```

本任务没有改变雷达质控、QPE、LK、STEPS 或 NowcastNet 的算法实现和产品契约。
