# RP-045 平台性能、五分钟更新与派生产品版本收敛实施记录

更新日期：2026-09-03

## 1. 背景与边界

当前福建雷达历史资料仅覆盖 2026-08-28。该数据足以验证解码、径向干扰处理、
格点、拼图、QPE、LK、STEPS 和公开权重 NowcastNet 的工程链路，但不足以建立可用于
业务验收的静态杂波图、海杂波/AP 分类器或跨天气过程人工标注集。

因此 RP-045 不继续用单日样本调低质控阈值，也不把 RP-042 的双偏振、垂直一致性诊断
直接提升为硬删除。当前 RP-043 仍是福建 `realtime_shadow` 的质控基线。下一轮质控算法
升级必须等待更多晴空、普通降水、强对流、台风和山地过程资料。

本轮聚焦不依赖新增气象资料、但能够立即改善稳定性和资源使用的四项工作：

1. 降低统一工作台聚合接口的重复计算和短时故障闪断；
2. 将 NowcastNet 的“起报频率”和“模型输入时间步长”解耦；
3. 将文件型 STEPS/NowcastNet 派生产品收敛为每个周期保留当前和上一个成功版本；
4. 修正主界面的数据语义和刷新行为，避免把 PNG 色阶下限称为真实点值。

所有 NowcastNet 结果仍为影子或离线结果，不能阻塞 LK，也不获得业务发布资格。

## 2. 实施目标

### 2.1 Workspace 响应缓存

统一工作台当前会在一次周期详情请求中组合分析、QPE、诊断、确定性产品、集合产品和
NowcastNet 文件产品。RP-045 在现有投影外增加一个有界内存缓存，先解决浏览器轮询和
多人查看造成的重复 fan-out；后续再把投影迁移到数据库 Read Model。

缓存只覆盖：

```text
GET /api/v1/workspace/cycles
GET /api/v1/workspace/cycles/{cycle_id}
```

不会缓存：

- 管理请求；
- 带 Authorization 的请求；
- 产品图片；
- 状态代理；
- 其他领域 API。

默认策略：

| 项目 | 默认值 |
|---|---:|
| 周期目录 TTL | 5 秒 |
| 周期详情 TTL | 15 秒 |
| 依赖 5xx 时旧成功响应延续 | 2 分钟 |
| 最大缓存项 | 256 |

每个成功响应生成内容哈希 ETag。浏览器发送 `If-None-Match` 时可得到 `304`；缓存过期后
若投影依赖短时返回 5xx，则继续返回最近一次成功结果，并通过 `Warning`、
`X-RainPulse-Cache: STALE` 和陈旧秒数显式说明，不把旧数据伪装成新数据。

该缓存是过渡优化，不替代权威数据库，也不改变任何周期或产品身份。

### 2.2 NowcastNet 每五分钟更新

公开权重和当前 MRMS 父模型的原生协议仍是：

```text
9 个输入帧，帧间隔 10 分钟
20 个输出帧，原生时效间隔 10 分钟
```

RP-045 新增独立参数：

```yaml
issue_cadence_minutes: 5
input timestep_minutes: 10
```

因此 10:05 起报可以使用：

```text
08:45、08:55、09:05、……、09:55、10:05
```

模型仍观察 80 分钟历史，输入间隔没有改变，只是每五分钟利用最新分析重新起报。该修改
不能把 +5、+15 等时效称为原生 NowcastNet 输出；当前工作台仍应在这些时效显示无原生帧，
后续若增加运动补偿插值，必须标记为 derived frame 并单独检验。

影子探测服务增加一个有界 RadarAnalysis 帧缓存。连续两个五分钟起报的九帧输入高度重叠，
默认缓存 32 帧后只需读取新增分析，避免每 30 秒从 MinIO 重复完整读取相同九帧。

新增五分钟历史/手动运行入口 `backfill_fujian_nowcastnet_shadow_5min.py`，复用既有公开权重、
全有效 tile、拼接门禁和 bundle 合同。它只改变起报选择，不改变九帧十分钟输入、原生十分钟
输出、缺测拒绝和影子资格。生成 manifest 显式记录起报频率、输入步长和调度版本。

### 2.3 当前 + 上一个派生产品版本

RP-044 的脚本型 STEPS 和 NowcastNet 产品在新结果成功后只保留一个版本。为兼顾空间占用
和算法结果回看，RP-045 统一为：

```text
每个 contract + grid + model + issue_time
保留最新 2 个成功 bundle
```

该策略仅作用于文件型派生产品：

- `rainpulse.ensemble-application-product-bundle`；
- `rainpulse.nowcastnet-shadow-product-bundle`。

以下数据不在自动清理范围：

- 原始雷达基数据；
- normalized/QC 极坐标数据；
- RadarGrid；
- Mosaic/QPE/RadarAnalysis；
- 数据库运行、任务和谱系记录；
- 模型权重、训练检查点和独立验证证据。

新的保留包装器先在同一文件系统的隔离临时目录运行原生成器。只有生成命令成功且 manifest
通过合同识别后，才把新 bundle 原子移动到正式目录，再按 `created_at` 只删除第三旧及更早
版本。生成失败、无产品或拼接门禁不通过时，当前产品和上一个产品均保持不变。

删除前再次核对 manifest SHA-256，避免规划后目录被改写时误删。目录先移动到同根的
`.retention-trash` 再移除，且不会跟随符号链接或删除未知合同目录。

默认：

```text
RAINPULSE_DERIVED_PRODUCT_KEEP_VERSIONS=2
```

允许 1～10，但工程环境推荐保持 2。

### 2.4 工作台刷新和显示语义

主界面不再因 30 秒目录轮询或预设切换无条件重读完整周期详情：

- 周期目录内容身份没有变化时，不触发详情刷新；
- 历史固定模式不启动目录轮询；
- “预报对比 / 质控排查 / 检验回放”只在浏览器选择已返回的面板；
- 详情刷新失败时保留当前地图，并显式提示缓存结果，而不是清空四图。

当前 PNG 像素读取只能反查色阶下限，不能得到原始数组格点值，因此界面将“点值”改为
“色阶值”。STEPS 默认面板显式标记为 `STEPS P50`；质量条显式标记为 T0 输入质量；
工程影子中的 `DBZH_QC` 显示为“质控后反射率”，不再误称业务质控。真实点查询、同步十字光标
和差值图保留到数据库 Read Model 阶段实现。

## 4. 操作方式

原入口保持不变：

```bash
RAINPULSE_DERIVED_PRODUCT_KEEP_VERSIONS=2 \
make regenerate REGEN_PRESET=pysteps-steps ...

RAINPULSE_DERIVED_PRODUCT_KEEP_VERSIONS=2 \
make regenerate REGEN_PRESET=nowcastnet ...
```

`regenerate_forecasts.sh` 已把两类文件生成器放入保留包装器。生成器收到的实际输出目录是临时
staging；成功后才进入正式目录。NowcastNet 预设调用五分钟起报入口，仍只发布 +10、+20…+120
分钟原生帧。

Workspace 缓存通常无需配置。需要临时禁用时：

```text
RAINPULSE_WORKSPACE_CACHE_ENABLED=false
```

## 5. 测试与验收

新增测试覆盖：

- 周期详情缓存命中；
- ETag 条件请求返回 304；
- 依赖 5xx 时在允许窗口内返回显式 stale 成功结果；
- 非 Workspace、非 GET 和授权请求不进入缓存；
- 10:05 等五分钟边界可起报，九帧仍严格相隔十分钟；
- 五分钟手动运行入口只选择完整十分钟历史和原生验证时次；
- 非五分钟起报被拒绝；
- 输入步长和起报频率不兼容时配置失败；
- 相邻探测复用未变化分析帧并按 LRU 淘汰；
- 每周期保留当前和上一个 bundle；
- dry-run 不删除；
- 未知合同和隐藏目录不删除；
- manifest 在删除前发生变化时 fail closed。

建议完整验证：

```bash
make contracts-check
make test-python
make test-regeneration
go test ./services/control/...
make lint
make build
make test
```

服务器集成验收还需记录：

1. `/workspace/cycles/{id}` 连续请求的 MISS/HIT 比例和 P95；
2. 30 秒探测中 MinIO RadarAnalysis GET 数量下降比例；
3. 连续三次同周期 STEPS/NowcastNet 重算后仅保留两个 bundle；
4. 当前和上一个 bundle 都能被完整读取；
5. 10:05、10:15 等起报输入时刻严格为十分钟间隔；
6. LK/STEPS 在 NowcastNet 不可用时保持正常。

## 6. 本轮明确不做

由于只有一天福建历史资料，本轮不做：

- 静态地物杂波概率图；
- 海杂波/AP 训练或阈值提升；
- 双偏振证据进入硬删除；
- 垂直一致性证据进入硬删除；
- 基于单日数据调整 QI 门槛；
- 原生五分钟 NowcastNet 模型训练；
- 业务发布资格切换。

避免为了“算法更多”而在没有独立天气过程验证时增加不可解释的误删风险。

## 7. 后续实施顺序

### RP-046：Workspace Read Model 和真实点值

目标：

- 将当前内部 HTTP/JSON fan-out 收敛为 PostgreSQL 物化投影；
- 周期、算法运行、面板、帧和阶段状态统一查询；
- 增加真实格点采样接口，当前 PNG 色阶读取改名并最终退出；
- 前端实时跟随使用 SSE，历史固定周期停止轮询；
- 增加同步十字光标和差值图。

### RP-047：NowcastNet 一等算法任务

目标：

- 从独立回算脚本迁移到 NATS 长驻 Worker；
- 每五分钟起报、十分钟原生时效；
- 同尺寸 tile 批量 GPU 推理；
- 输入 halo + 中心可信区拼接；
- 保留集合成员并生成 P10/P50/P90、超阈值概率和离散度；
- NowcastNet 失败永不阻塞 LK/STEPS。

### RP-048：福建质控数据准备

在获得更多福建资料后再实施：

- 按雷达/仰角建立晴空静态杂波图；
- 冻结晴空、层状降水、强对流、台风、山地和已知干扰过程；
- 增加标注工作流；
- 时间连续性、三维垂直一致性和邻雷达一致性先 diagnostic-only；
- 以异常 Precision/Recall、真实降水保留率、QPE 和 FSS 联合决定是否进入 QI。

### NowcastNet 训练轨道

先评估已完成的 300,000 步演化网络，再运行 10,000～20,000 步生成阶段开发试验。只有
开发集相对公开权重明显改善，并且接近或超过 STEPS 的主要概率基线后，才批准完整
500,000 步生成阶段训练，避免直接投入约 276.9 GPU 小时。
