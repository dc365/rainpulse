## 已确认的现有代码缺口

1. `radar/fmt.py` 只接受 generic_type=1；Go `radaringest/probe.go` 也按普通FMT偏移探测时间。两个入口必须同时支持格式16。
2. `ingestapp/main.go` + `Manifest.WithSourceSettings` 把单个 BDP data_code 的根目录覆盖给全部站点，不能混接两个源。
3. 常规 scanner 依据当前时间、目录日期和文件mtime回看；历史导入需要明确日期区间，不能依靠手动复制后的mtime。
4. 多波段 native 上限32层/800万门、网络与输入上限16站，不足以覆盖实际样本和24X+5S网络。
5. `Executor` 当前读取所有输入体扫，X QC又复制数组；仅调大常量会把内存压力成倍放大。
6. 产品cadence在Go、Python和schema中固定为60秒。六分钟抽样不应扩展出六倍重复帧。
7. 当前融合使用站级固定波束宽度；相控阵需要保存并优先使用逐cut/beam几何。

## 推荐设计

```text
S/X只读目录 → Go按源发现/归档/登记 → 常驻格式解码Worker → 标准化资产
                                              ├─ S既有QC资产 ─┐
                                              └─ X候选QC ────┤
Go operations冻结六分钟任务 ────────────────────────────────────┤
                                                             ↓
                                                分层选源/候选产物 → Go预览 → Web
```

### 1. 双数据源，沿用原登记链路

在既有 ingest source 声明增加 `data_code`；旧source缺省继承现有 `radar_input.data_code`，保持旧部署兼容。按不同data_code分别解析BDP根目录，按source应用，不再全局覆盖。测试导入使用上述明确目录和UTC区间 `[2026-08-28T00:00:00Z, 2026-08-29T00:00:00Z)`；文件头时间作最终筛选。

历史导入复用原始归档和体扫登记的幂等键，提供预览清单与执行两步。递归发现后校验文件名/头站号/别名、格式和扫描边界，按原始SHA识别重复及同名不同内容。源目录只读；原始归档只登记并保存一次，不为每个六分钟任务复制原始文件。新X登记只触发解码，不进入S自动QC/QPE链路。

### 2. 格式分流与标准化

扩展既有解码入口：普通FMT继续原路径；格式16进入独立的相控阵解析模块。保留原始矩值码、scale/offset、缺测码、逐射线时间/方位/仰角、cut及beam索引、厂商矩值身份。输出既有标准化Zarr合同的向后兼容扩展，并记录源格式profile。

逐cut保存波束几何和真实距离库；不能用任意常数填0波束宽度。统一频率为Hz、高度为已核验MSL，但转换依据必须来自设备族格式说明及站点资料。MSL、1985高程和椭球高保持显式来源，复用已有vertical_datum能力。无法核验几何的站允许登记、解码和原生预览，保持空间融合禁用。

PyCINRAD只用于冻结样本的独立交叉解码验证；生产继续维护现有严格读取器，避免额外引入一套调度或数据模型。

### 3. 明确六分钟样本产品

网络/请求合同升级为可识别的新版本，产品cadence只允许已支持的60或360秒，首个回放产品选360秒。站点真实采集周期与本批抽样策略分别记录；不因文件夹六分钟抽样就断言所有设备原生周期相同。

产品时次按UTC六分钟整点展开，选体扫结束时间不晚于产品时次的最近有效体扫。保留每条射线年龄，不能用后来的体扫倒填过去。初始候选最大年龄420秒，沿用射线级超龄拒绝；超过阈值保留缺测并显示原因，不用长时间维持旧图来填满缺口。扫描从00:00持续到00:01的文件不参与00:00产品。

历史cutoff使用本次冻结清单时刻，明确标注回放；不假装它是当日实时可得性。单批保持最多1小时、64任务，全天拆分为小时批次，不扩大一次提交范围。

### 4. 有界读取与融合

将原生cut数量上限设为64，保留单字段形状、总解压字节和单任务预算检查。取消必须把整个大体扫装入内存的路径，按站/扫层读取所需字段，执行X QC后释放；相位处理按完整射线门序列运行，不能跨分块丢失相位中断状态。

融合按输出tile保持各高度层的当前赢家，逐输入扫层更新，最后求垂直最大值。来源排序固定，块尺寸与输入顺序不能改变数值结果。保留可校验的Zarr分块或已有打包索引，不把全体扫强制编码成一个巨型NPZ，不产生逐门文件。

需要同步扩展VerifiedArtifactReader的逐逻辑对象/分块读取接口；只修改融合循环而继续调用一次性session.load不能降低输入峰值。旧打包资产仍执行完整性校验，可用有界临时落盘完成，不能以选择性读取为由跳过原有承诺的哈希验证。

首轮区域网络控制在16站以内；完成内存验收后再将网络/请求/Go/Python的一致上限扩展至32，支持全量29站。输入站数的扩大必须与流式读取一起交付。读取仍核验标记/对象哈希，损坏或预算溢出可定位至站/扫层。

### 5. 产品与科学资格

S只读取现有QC，并保留原硬拒绝、withheld与版本资格。X输出原生矩值预览、基础QC、单站候选、S+X组合候选及源站/年龄/高度/分辨率证据。

首轮X的衰减模式为 `none`，明确保留不确定回波；厂家原始/订正状态未知时不追加PHIDP订正，不声称X已进入可信CR。经设备说明、标定和样本核验后逐站开启相位或上游订正模式。产品仍candidate-only、QPE资格关闭。

首个融合区域选福州：ZF101–ZF105 + 已有S站Z9591/Z9593。候选米制网格使用EPSG:32651、500m间距、与既有福州范围118–123E/25–27N相交的有效覆盖；投影包络向500m整数格外扩，明确像元中心/边界。共同MSL层采用250、500、1000、1500、2000、3000、5000、8000、12000m。网格细度不代表实际观测分辨率。

最小可交付范围是ZF101的一份文件完成严格解码、原生预览与质量报告；几何未核验也可交付此结果。随后完成一组经核验的S/X重叠区域回放，再扩至24个X站。Z9595单独完成站点配置/QC验收后加入，不借用其他S站配置。

### 6. 运维与验收

复用Go控制进程、原解码Worker及已部署multiband operations Worker入口，不增加常驻服务种类。先单计算lane、小时间窗运行，再依据峰值RSS、吞吐和现有队列延迟设资源配额；现有机器24逻辑CPU、约156.6GiB内存不是可任意占用的预算。

独立可交付批次：
1. 双源历史登记与两类格式标准化：交付站点清单、严格解码、单站预览，失败隔离可见。
2. 六分钟区域S/X候选：交付有界输入、几何/订正资格、候选预览和归因。
3. 全站全天回放：流式资源验收及32站合同通过后按小时提交，保留缺口、异常站和失败清单。

实现涉及超过8个文件；主要位置为Go的bdpruntime/radaringest/ingestapp/controlplane/multiband、Python的radar/fmt/config/zarr_volume与multiband适配/执行/融合、对应schemas、站点配置和管理端产品时钟展示。增加声明字段、标准化格式profile和历史导入入口；不增加新的状态数据库或外部账号。现有SSH、PostgreSQL、对象存储、NATS权限即可实施，运行时不依赖外部网站。

验证命令沿用 `bash scripts/test_multiband.sh`，增加Go radaringest/bdpruntime/ingestapp、Python decoder及S QC回归；完整Linux/前端构建使用 `bash scripts/build_realtime_shadow.sh --unified`。新测试必须覆盖普通/相控阵格式、24 个平级站目录、站号别名、39/40层大样本、UTC日界/秒偏移/体扫结束、重复/截断/缺矩值/缺站、六分钟输出数量、禁止未来体扫、内存超限、块尺寸与输入顺序等价，以及已有S结果不退化。

现场验收先运行各设备族代表样本；核对独立解码的矩值、门距、射线时间、层数和缺测语义，再跑30分钟区域回放，记录峰值RSS及耗时。随后按小时扩至全天。真实一分钟吞吐与技能验收需要将来完整一分钟序列，不能用此次稀疏样本替代。

失败处理：坏站/坏文件留在隔离清单，不自动放宽格式或科学门控。升级失败时停止候选接单，保留已提交任务/候选对象和已登记原始资料；回退不删除数据，也不让旧Worker领取新合同任务。

## 前提与资料缺口

主要前提是能从厂家说明或正式站点档案核验波束几何、频率单位、高程基准及上游订正语义。若无法核验，仍交付登记/严格解码/原生预览，但对应站的空间融合与可信资格保持关闭。不能把缺少档案转化为默认已核验。

设备/数据提供方负责说明单位与校准来源；接入实施负责提取字段、生成差异清单和阻断未核验配置。这是逐站准入条件，不妨碍先实现可验证的文件解码与历史登记。
