# X 波段质控对照与 S/X 融合界面接入方案

日期：2026-09-25。状态：候选实现与部署验收中。源码核对基线：main `98ebe0c`。

## 现状与目标

X 历史登记、两类 FMT 解码已交付，代表站 ZF101、ZF505 已有标准化资产。现有 multiband 模块提供候选 X QC、分层质量选源和组合反射率计算；后台 NewRun 提供 x_qc、sx_composite 入口。2026-09-25 只读检查 105：rainpulse.service active，候选解码容器健康，没有运行中的 multiband 容器。此前的四份 X 样本只验收到 NORMALIZED，不能称为质控或融合产物。

主工作台尚未贯通 X 质控对照和 S/X 产品目录。当前产物只有投影网格快视图，不是可直接贴到经纬度地图的瓦片。后台还把融合写成“一分钟”，与本批六分钟资料不一致。

本方案交付两个可独立验收的功能：X 单站原始/质控对照；S 单独、X 单独、S/X 融合的区域对照。沿用现有 Go 控制面、Python 常驻 Worker、对象存储及 React 地图，不新增服务种类、外部账号、API 密钥或算法库。

## 已核实的实现约束

- managed.Executor 当前即使 mode=x_qc 也调用 build_composite，独立 QC 被网络空间几何门控牵连；须先拆开执行分支与配置校验。
- quality.x_qc 的 DBZH_QC 保留数值与诊断，不等于按最终动作过滤后的显示场；不能简单绑定为“质控后”。
- attenuation=none 时 propagation_good 为 false；未知标定也阻止 REFLECTIVITY_ELIGIBLE_FOR_CR。当前 X 配置因此不能宣称已参与合格融合。
- model 当前 MAX_SWEEPS=32、MAX_GATES=8,000,000；ZF101 实际 40 层、约 2342 万 REF 门。单独上调常量不能解决全体扫读取与复制的内存问题。
- 主界面当前以 workspace/cycles 作为目录。独立 X 资料不能依赖已有 S 起报或预报 cycle 才能被发现。
- 遵守 AGENTS：原始极坐标 QC、缺测/无雨/低质量分离、UTC、六分钟产品、React 只调用 Go、候选不自动取得业务资格。

## 推荐交付顺序

### 第一批：独立 X QC 和可查看的前后对比

最小方案是只在任务详情放两张图片；建议同时把独立目录接入现有“质控排查”，这样没有预报起报时次的 X 历史资料也能直接选择、回放和定位失败原因。

1. 在现有“质控排查”增加 S/X 波段筛选，选择站点、日期、真实体扫和仰角。X 时间轴列真实体扫时间，显示起止时间；显示 UTC+8，并保留 UTC 明细。默认展示最新成功的同一版本结果，用户可切换历史版本。
2. 左右联动显示“原始反射率”“基础质控后反射率”。同一 scan_id、cut、空间范围与色标，不能把不同时间或不同层自动拼成对照。低层默认选择实际最小仰角，并显示 cut 编号，保留重复仰角扫层。
3. 可切换“质控动作”“原因”“SNR/RHOHV/PHIDP/KDP”辅助层。鼠标点查展示原值、处理值、动作和原因；强回波保留率等只作为变化统计，没有真值时不显示准确率。
4. 明确四类动作：保留、确认剔除、疑似待核、缺测；无回波另外保留有效观测身份。疑似以独立可开关覆盖层展示，不作为已确认杂波。标定未知、衰减未知是资格状态，不自动让基础对比整图消失。
5. 新增明确语义的显示字段 DBZH_QC_DISPLAY、QC_ACTION、QC_REASON；保留 DBZH_RAW、处理值、原始矩值和完整原因。显示掩码只改变渲染，不覆盖数值资产，也不提升 CR/QPE 资格。记录厂家订正状态，首批不追加未知来源的衰减订正。
6. 拆分原生 X QC 配置与空间网络配置：基础检查只要求已核实的原生坐标、单位与站号；MSL、波束或频率未核实不会阻断原生预览，依赖这些资料的检查明确标记未执行。若经纬度也未核实，显示以站心为原点的原生 PPI，不伪装成地理地图。
7. 按扫层读取、处理和写出；涉及相位的处理保持整条径向连续。保留对象完整性验证、解压大小约束和任务资源预算。先解决真实 39/40 层样本，再扩充准入上限。

这批独立可用：即使空间资料仍缺失，用户也能看见 ZF101/ZF505 的基础质控对比和不能执行的检查原因。

### 第二批：区域 S/X 候选对照

在主工作台增加“S/X 融合”预设，沿用同步地图、缩放、十字光标和播放控制。默认三栏：S 单独、X 单独、S/X 融合；辅助选择“融合减 S 的差值”“来源波段/站点”“观测年龄”“取样高度”“不确定回波”。差值仅在双方都有有效回波且单位相同的像元计算；新增覆盖单独标识，不能把缺测当 0 dBZ。

1. 三栏必须由同一冻结输入清单、同一网格/高度层、同一六分钟时次生成。S 单独也经同一组合算子重新投影已有 S QC，不拿不同算法的旧图直接对比。X 单独是同区域所有准入 X 的组合结果。
2. 复用现有同高度按质量选源、再取垂直最大值的组合反射率方法；不直接平均 dBZ。先复用经核验的 S QC，不重新套 X 算法处理 S。
3. 时次步长 360 秒，采用结束时间不晚于产品时次的最近有效体扫，初始候选最大年龄沿历史方案为 420 秒；实际逐射线年龄仍检查。缺站、超龄、无资格分别显示，不倒填未来观测。
4. 原计划首个区域为福州 ZF101–ZF105 与 Z9591/Z9593，500m 候选网格和既定 MSL 层。只有逐站核验并登记完成的站参与，UI 显示计划站与实际参与站。不得用未知高度或 0 波束宽度填默认值凑齐网络。
5. X 未有合格贡献时，清楚显示“本时次 X 未参与”及原因；允许查看不确定 X 诊断层，但不能将其命名为合格 S/X 融合。空间几何未核验的 X 不投影参与空间组合。
6. 每个像元可查贡献站、S/X 波段、原始 scan_id、年龄、实际高度、分辨率和质量分；图头明确“组合反射率候选”，QPE/预报资格继续由独立验收决定。
7. 将数值网格通过已有地理渲染链路生成带明确 CRS/范围的地图资产；禁止把当前 cr.png 当经纬度矩形直接拉伸叠加。

这批在无 X 准入时仍可用：展示 S 基线、X 缺资料原因和逐站准备状态；科学融合验收只有至少一站 X 实际合格贡献后才算通过。

## 数据与接口

```text
标准化 X → 独立 X QC → 原生对照资产 ──────────┐
                     └→ 合格 X 观测 ─┐     │
已有 S QC ────────────────────────────┤     │
冻结六分钟任务 → 同网格 S / X / S+X 产物 ────┤
                                           ↓
                         既有产品登记 → Go 目录/详情/点查 → React
```

先扩展 contracts/openapi.yaml 和内部产物 schema，再实现接口。建议使用只读 `/api/v1/workspace/radar-products` 目录和 `/api/v1/workspace/radar-products/{product_id}` 详情，接受 kind、radar_id、时间范围、游标；产品 kind 为 x_qc_compare、sx_composite_compare。这里 product_id 为唯一产物身份，另设 product_definition_id 表示冻结网络里的产品定义，避免混用。点查沿用 workspacepoint 能力并为新产品定义字段。

目录摘要包括 band、scan_id 或 analysis_time、cadence_seconds、processing_status、eligibility、缺失原因和版本；详情返回有界的图层清单、图例、坐标、输入来源、统计和点查入口。大数组仍留对象存储，API 不传完整雷达数组。登记复用既有资产/operations 完成记录，按成功标记发布，刷新与 SSE 沿用现有机制；无结果也能通过资料台账呈现“已解码/待 QC/参数缺失/失败”。

后台重算继续使用 x_qc、sx_composite 预设，产品从目录选择，时钟文案取 cadence_seconds。X QC 与融合分别呈现就绪检查。已有 Worker 池恢复接单前必须验证镜像、资源配额、版本和任务身份。

## 文件范围与验收

预计超过 8 个文件，涉及 contracts/openapi.yaml、contracts/internal/multiband、multiband 的 model/quality/managed/product/codec/fusion、Go operations_multiband、workspace/workspacepoint，以及 Web MainWorkspace、workspace model/catalog、admin/NewRun。复用现有渲染与任务机制，不增加新的服务体系。

自动验证沿用 `bash scripts/test_multiband.sh`，加对应 Python/Go/React 合同测试。必须覆盖：普通与相控阵格式、39/40 层、同体扫对照、动作掩码、缺矩值、未知订正、缺测与无回波、未来体扫拒绝、六分钟日界、缺 S/缺 X、全 X 不准入、S 硬拒绝不泄漏、块大小/站序数值一致、损坏资产、预算超限、产品失败后的界面状态。现有仓库 CI 失败需逐项区分基线问题与新增回归，不能用专项通过代替全部通过。

105 验收按顺序：ZF101/ZF505 各一份完整体扫前后图及点查 → 两类设备一段 30 分钟基础 QC 回放 → 首个已核验 S/X 重叠区域的五个连续六分钟候选时次 → 记录峰值 RSS/耗时后按小时扩量。首批内存验收沿用已试过的 4GiB 单计算 lane 上限；超限则优化读写或缩小单批，不能无记录增加并发。界面必须实际可进入、有时间可选、有图可看、点查能追溯、失败可解释。

最脆弱前提是 X 空间与标定资料能获得核验。资料由设备/数据提供方给出，接入方登记依据；若缺失，第一批仍交付，第二批相应站明确不准入。不得借界面需求绕开此门控。

上线按独立两批提交、部署、验收。回退时先停止新候选任务和隐藏新入口，保留已生成资产和原始资料；旧成功产品可继续读。工作量预估第一批 3–5 个工程日，第二批 4–7 个工程日，另计站点资料核验等待与全站全天运行时间。未包含全 24 站资格验收、可信 X QPE、预报输入替换或实时一分钟吞吐验收。

## 实施状态（2026-09-25）

第一批实现已在独立工作树：主工作台 QC 工具栏增加 X QC 入口；管理重算文案改为六分钟候选；X 单站任务只运行原生极坐标 QC，产出逐仰角原始 PPI、基础 QC PPI、确认/未决标记图层；任务预览支持同扫层并排查看。序号与源扫层编号分开展示，站心图不使用未核验地理坐标；疑似门保留回波强度并以琥珀色标记，确认拒绝门从显示场遮去。

Python 与 Go 网络契约现在允许仅含 X QC 站点、无空间网格、无站点几何的独立候选配置；该能力不放宽区域融合的空间/标定门控。normalized Zarr X QC 按扫层读取、质控并释放，允许最多64层、每层不超过800万门、全扫体不超过3200万门，并分别校验压缩输入与累计解码预算。40扫层 Zarr 合成体扫已通过 Worker Executor 路径测试；这不是 105 上实际 39/40 层资料的 RSS 验收。

`bash scripts/test_multiband.sh`、Web 全部测试/构建及改动文件 Ruff 检查通过；脚本按设计跳过了需要显式授权与临时数据库的 PostgreSQL 集成测试。105 上 multiband Worker、X QC 独立发布配置和真实样本资源测量仍未完成，因此生产部署尚不能生成或展示该数据的 QC 对照。

第二批现已完成候选实现：`sx_composite` 同一冻结输入生成 S-only、X-only、S/X 与仅共同有效像元的 X−S 差值，四张快视图和数组共享同一投影网格及六分钟时次；流式融合在有界内存/磁盘预算内一次扫层计算三套网格。工作台已有“S/X 六分钟区域对照”入口，任务详情显示四图对照及融合状态。当前入口指向运维候选任务，不是主工作台产品目录；快视图仍是投影网格图，不是带 CRS 的地理瓦片，尚无地图联动或逐像元空间点查。因此这一交付只覆盖可复核的候选任务预览，不满足原方案所列产品目录/主地图完整验收。

候选清单按每个波段实际合格回波和无雨像元标记贡献波段；单波段贡献时明确标为“仅 S/X 贡献”，不称为双波段融合，并显示未贡献波段的原因。X QC 默认选择实际最低仰角，原顺序和重复仰角层均保留。区域快视图加载失败可单独显示错误并重试。

本轮最终复验：`bash scripts/test_multiband.sh`、Web 全量测试（135 项）、Web lint/build、改动文件 Ruff，以及完整 Go 仓库测试和 vet 均通过。Web lint 有 6 条既有 warning，无 error。测试脚本按设计跳过了需要临时数据库与显式授权的 PostgreSQL migration integration。额外修正了最终融合无回波时错误沿用单波段回波标签的问题：融合的回波波段现在依据最终 `WINNER_SOURCE` 统计，并覆盖“单波段有回波、最终只留下有效无回波”的回归测试。

当前变更已重放在 `origin/main` 的 `98ebe0c` 上；PR、主分支 CI、合并、Linux 部署构建和 105 候选产物暂存仍待完成。105 缺少经核验的 X 站几何、MSL、频率与标定配置，也尚未用 20260828 的真实 X/S 配对体扫完成资源及数值验收；已实现代码只能以候选状态发布，不能启用该 X 站参加空间融合或业务产品。
