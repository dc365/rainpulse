# 统一 S/X 雷达质控工作台设计

## 依据与修订

依据 2026-09-25 用户提供的两张截图与要求：波段切换简单，方便分别验证 QC，使用统一地图框架，支持后续同图叠加与融合验证。

本设计取代此前“独立 X 浏览视图”的页面组织方式；保留已实现的真实体扫目录、图件身份校验、候选资格与公共色谱。当前问题是信息结构分裂，而非仅按钮颜色不一致。

## 1. 固定的信息层级

1. 应用导航：预报对比 / 质控排查 / 检验回放。
2. 质控任务：单站验证 / 同图叠加 / 融合验证。
3. 当前任务的资料选择：波段、站点、仰角、显示字段。
4. 地图内工具：双图/卷帘/单图、底图、图层透明度、复位、支持时的点查。
5. 底部唯一时间区：实时/历史、日期时间、前后帧、播放速度、可用性轨道。

禁止将后台任务入口、资料日期、波段导航、图层开关混排成一串链接。

## 2. 首屏：单站验证

```text
RainPulse                         预报对比  [质控排查]  检验回放  后台
[单站验证]  同图叠加  融合验证
波段 [ S | X ]   站点 [站号·站名 ▾]   仰角 [0.50° ▾]   字段 [反射率 ▾]   ⋯
┌──────────────────────────┬──────────────────────────┐
│ 原始反射率                │ 质控后反射率              │
│                          │                          │
│         同一地理范围、同一底图、视角联动               │
│                          │                          │
└──────────────────────────┴──────────────────────────┘
[双图 | 卷帘 | 单图]   底图   质控标记   复位             统一 dBZ 色标
历史 [2026-08-28 08:06 ▾]       上一帧  播放  下一帧  速度
──────────────────────────────●─────────────────────────
原始资料 ●●● · ●●             质控结果 ●● · · ●●
```

- S/X 是同一个分段控件，固定位置，一次点击完成切换，留在当前工作台。
- 每个波段记住上一次站点及扫层。切换保持目标时间、布局、视野；首次进入站点允许“定位本站”显式动作。
- 仰角保留原生编号及真实角度，禁止通过同一数组下标映射不同雷达的扫层。
- 默认只显示原始/质控后双图；组合反射率和 QPE 不再占据单站验证的默认四图。
- 双图/卷帘共用同一视角状态。数据尚未配准时只提供可用布局，不将原生 PPI 冒充地理图。
- 图头只保留站号、原始/质控后、仰角、实际观测时间、候选标识。长站点参数、结果版本、scan/task ID 收进“资料详情”抽屉。
- “生成/重算”“高级证据复核”移入 ⋯ 菜单；已有后台链接继续兼容，但不作为工作台主导航。
- 质控标记是统一图层开关，具有独立分类图例，不污染反射率色谱。

## 3. 同图叠加

- 保持相同外壳、底图和时间轴；改成一张地图。
- 资料选择区变成可收起的图层面板，按 S、X 分组，可选多个站点。
- 每个图层包含：站点、原始/质控后、仰角、实际时间/相对目标时间偏差、可见性、透明度和排序。
- 默认加载当前 S 站与当前 X 站的质控后图层；未定位站保留在目录并显示待核验状态。
- 透明叠放用于空间检查；“仅 S / 仅 X / 叠加”是该视图内的快捷显示控制。
- 视觉叠放不命名为“融合”；不通过 alpha 混色或 dBZ 平均产生融合数据。

## 4. 融合验证

- 使用同一地图框架；入口存在，但只有已生成且身份完整的融合候选可以查看。
- 默认三栏：S 单独贡献 / X 单独贡献 / S+X 融合候选，地图范围和时间联动；单图布局可以切换这三类产品。
- 可增加共同有效区域差值、来源贡献、质量和观测年龄图层；缺少数值产品时明确不可用。
- 对比必须来自同一产品定义、空间网格、层/高度语义和目标时间；不直接把两个站点不同仰角 PPI 当作融合贡献对比。
- 候选与业务准入分别展示；可查看地图不等于满足融合或 QPE 资格。

## 5. 同地图的数据前提

现状核对：S 前端有站点地理元数据；当前 X 目录 API 输出 geometry_status=unverified，图件仅为 station-centred polar PNG，没有经过核验的地理栅格定位信息。

分开两个门槛：

- **地图显示资格**：核验文件头站号、经纬度及坐标参考、方位/距离原点、门距和扫层身份；建立有追溯来源的站点目录。后端从原生极坐标数值生成有 CRS、bounds/transform、有效掩膜与配准版本的地图图层。不能仅给方形 PNG 配一个经纬度外框。
- **融合资格**：另行核验高度基准、时间窗、标定、波束/覆盖和质量门控。只在满足相应产品条件时启用真实融合结果。

元数据可从原始文件头及已有解码结果提取，但需要对照站点资料核验，文件头存在数值不自动意味着可信。未核验期间仍在同一工作台以明确的“原生坐标”状态提供单站 QC；不能叠到地理底图。此状态不会另开一套页面。

## 6. 统一时间与选择状态

- 统一状态：mode、band、station selections、target time、sweeps、field、layout、map view、result identity。
- 只有底部日期入口，时区统一北京时间；内部存储 UTC。
- 单站时间轴读取真实观测/质控目录，不再用预报 0–180 分钟时间轴冒充 QC 资料。
- 联合视图以六分钟产品窗口选择输入，具体体扫使用后端固定匹配规则，返回真实起止时间、年龄和匹配理由。缺测留空，禁止无限最近邻或自动换日期。
- 切 S/X 保留目标时刻；没有满足时间规则的数据时明确显示“该时刻无资料”，提供跳转到最近有资料的显式操作。
- 时间轨道显示原始/质控可用性；叠加模式可展开 S/X 各自的可用性。拖动同一游标更新所有图层。
- 同一结果 raw/QC 成对发布到界面，避免快速切换时新旧图混用；异步请求绑定选择身份。

## 7. 组件与接口落地

- 一个 RadarQCWorkspace 外壳，复用现有 RasterGISMap、SharedTimeline、ReflectivityLegend。
- RadarQCControls、RadarLayerPicker、RadarQCDetails 是公共组件，按任务模式传入数据；删除 S/X 各自重复工具条。
- S/X 数据适配器汇总到统一 Station / Scan / Sweep / QCResult / MapLayer 视图模型。保留各自原生标识，不以 UI 显示名称代替身份。
- 扩展站点/结果契约，返回 geometry status/provenance、地理资产定位、字段单位、palette version、资格原因；React 仍仅通过 Go 访问。
- 已有 X result 分享 URL 和 S 历史链接解析到公共状态。旧独立入口重定向到质控工作台，不再保留醒目的文字导航串。
- 窄屏保持同一层级，资料选择紧凑换行，图层/详情收进抽屉；地图采用单图切换或上下对照，时间轴控件保持可达。

## 8. 实施顺序与验收

A. 统一外壳和交互：删除重复入口、集中波段/站点/仰角、统一日期位置、默认双图、状态与链接迁移。验收 S→X→S 一次切换且保留目标时间，缺数据不偷换时刻，两个波段相同控件顺序。

B. X 地理配准：从两站样本核验元数据，生成地理图层，站点落点/方位/距离/海岸与控制点交叉核验；接入同一 RasterGISMap。验收原始/质控同站同层配准一致、拖放缩放联动。

C. 同图叠加：多站图层面板、时间匹配状态、透明度与排序。验收 S/X 在同一地图独立开关，缺测及过期图层不会残留。

D. 融合验证：接入真实候选的 S-only / X-only / fused 与贡献证据。验收同网格同时间、候选身份清晰、不把透明叠放视为融合。

每批遵循本地测试与 main 合并后部署 105。A 可以先交付，B 的核验结果决定可进入地图的 X 站，C/D 依相应数据资格启用。
