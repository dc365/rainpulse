# X 质控：清除比例与残留结构收尾

## 目标与当前边界

本轮收尾清除比例警告误报，以及超限时丢失细径向、断续碎片候选位置这两项。
远距离强斑块的天气/干扰混杂归因单独保留，不扩展本轮检测阈值或研究范围。
本记录是新的修复工作，不替代之前候选发布的历史验收，也不表示所有 X 质控已完成。
只使用唯一工作目录；保留共享 S、Web、Go 未提交改动。小时跟进保持暂停。

## 已核实的清除比例错误

对已发布版本 `875c6c6` 的冻结 22 个体扫、198 个原始仰角层，重新读取所有
原生数组和证据，并核对产品、输入及任务身份。27 个警告中，17 层的核心形态
警告由独立噪声质控与形态提名的重叠计数触发。未重复计算时，其新启发式提名
确实低于原有比例上限。

原 `core._evaluate.finalize` 用整个提名并集判断上限，随后又把拥有独立完整性
上限的 noise censor 加入最终动作。这违反了该函数中“censor 不受启发式上限
控制”的约定；四个增量集成模块已经正确排除这个重叠。
修复在两个核心计数分支排除已经独立判定的 censor，并记录分母、比例、上限、
未被 censor 覆盖的基线/并集计数与重叠计数。上限、检测阈值、天气保护不改变。

198 层中，核心超限标记与可见质控反射率的交集为 0，进入 CR 的交集也为 0。
这些警告不能全部解释成“没质控”：核心把它们保留为不确定，已经从显示和 CR
中排除。修正计数后的画面变化必须另行测量，不能用警告消失代表清除效果改善。

## 已核实的增量候选丢失

窗口、碎片载体与 SNR 载体三个集成模块在动作上限拒绝时清空候选，没有保留
其原生位置。核心和完整扇形模块已采用的超限待复核语义没有贯通这些增量。
原始资料重跑恢复的七条模块记录，其候选数量与已发布证据中的合格数量完全
相等，并且存在仍然显示的成员。各模块计数可能重叠，不能相加宣称独立收益。

三个模块新增独立 BUDGET_REVIEW_MASK，接受掩码仍为空、状态仍为 4，保留原因
与 ACTION_BUDGET；现有唯一写入流程将其标为不确定并排除 QC 显示和 CR。
原始值、已确认隔离与父级动作保留。资源、保护/来源或证据拒绝不产生待复核
动作；组合证据溢出在附加原因之前整体撤回增量。窗口模块还修复了已存在
待复核成员被重新纳入已接受提名的问题，仅允许新增成员进入增量。
完整语义见 [动作上限与待复核契约](../contracts/data/xqc-action-budget-review.md)。

新增回归实际运行旧依赖得到三个丢失位置失败及一个窗口父级状态失败；
修复后冻结完整 X 套件 604 通过，0 跳过。覆盖三种模式的真实唯一写入流程、
原生导出、天气保护、资源及组合证据原子拒绝。最后一项测试断言仅换行，
AST 与已验证版本一致，冻结依赖下 15 项相关测试通过，新增 lint 问题已修正。

减少 1,594 个先前仍可见的候选像元，其中 133 个原 QC 值至少为 35 dBZ。
这些成员保留为不确定，不宣称已证实是干扰。独立核对逐层源/代码/原生/PNG
SHA 与待复核数组；原始值、几何、保护、已确认隔离和既有拒绝保留，待复核
之外的 QC 数值逐值一致。两个独立对照及真实超限对照的 QC 数值不改变。
