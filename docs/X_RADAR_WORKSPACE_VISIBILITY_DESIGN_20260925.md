# X 波段站点与质控结果主工作台设计

状态：设计稿，尚未实施。日期：2026-09-25。

## 目标与现场证据

用户从主工作台“质控排查”选择 X 波段、站点和真实体扫，即可查看同一扫层的原始/基础质控后图。没有结果的站点也必须可发现，并说明处理到哪一步。

本次只读核实 105：multiband Worker 就绪；候选作业 `64d48b88-ce64-4748-abcc-f93ac57634d3` 成功，包含 ZF101（40 层）与 ZF505（9 层）。两个任务的 manifest 和最低层 raw/qc PNG 均返回 HTTP 200。结果标记 candidate_only=true、operational_eligible=false、qpe_enabled=false。不能据此宣称全站/全天 QC 或业务融合完成。

目前 `MainWorkspace.tsx` 的 X 入口跳到后台新建任务，`workspace/model.ts:radarIDs` 从预报周期的 panels/radars 取站；候选任务未进入该目录。ZF101 的原始资料台账仍显示 NORMALIZED、qc_uri=null，但独立候选任务已经成功。这是两个不同的状态，不能依赖 qc_uri 判断候选 QC 是否存在。

## 选择的方案

最小方案是给成功任务增加直达链接，但只能看个别任务，不能发现全部站点与缺失时次。推荐在既有“质控排查”内增加独立 X 资料浏览视图，复用已有候选图件、Go 资产校验与 Web 图例。S 波段现有流程继续使用现有周期目录。

使用者是正在核对 20260828 样本的雷达人员；首要动作是选站、选扫层、辨认被处理的回波。界面沿用当前主工作台的低对比边框和紧凑控制条，把空间留给回波。领域元素为波段、站号、体扫起止时间、仰角/扫层编号、原始反射率、确认剔除、未决回波。颜色沿用蓝/绿/黄/红/紫反射率色阶；状态以文字加符号表达，未决标记使用现有琥珀色，缺测透明。默认的统计卡片替换为可选站点清单，任务列表替换为观测时间轴，后台跳转替换为直接同扫层对照。

## 页面结构与交互

```text
质控排查   波段 [S] [X]   日期 [有资料日期]   [站点清单]
┌────────────────┬──────────────────────┬──────────────────────┐
│ 搜索站号/名称   │ 原始反射率           │ 基础质控后 · 候选    │
│ ZF101  可对照   │                      │                      │
│ ZF505  可对照   │ 同一站、同一体扫、同一扫层；联动缩放/平移   │
│ 其他站 按实标注 │                      │                      │
│ 待解码/待QC/失败├──────────────────────┴──────────────────────┤
│                │ 仰角 [0.90° · 第1层 · 编号0] [质控标记]     │
└────────────────┴─────────────────────────────────────────────┘
体扫时间轴：真实观测起止时间、可用/待处理/失败状态、上一扫/下一扫/播放
来源详情：scan_id、任务/版本、原始格式、坐标核验状态、业务资格
```

- 波段和站点来自服务端目录；不硬编码 X 站号，也不依据旧 ZF900 目录归属判断身份。
- 左侧固定约 220px，站点较多时滚动与搜索；窄屏折叠为站点抽屉。清单显示站号、可选名称、资料数、可对照数和状态；具体数目由目录返回。
- 初次进入 X 视图选最近有 X 资料的日期，并明确显示为历史资料；有成功结果时选最新成功体扫，没有则选最新登记体扫。20260828 样本不能被默认“今天”过滤掉。
- 站点发现与结果就绪分开：发现但未登记、已登记待解码、已解码待 QC、计算中、可对照、失败、资产不可用。坐标核验和业务资格分别展示，不塞进同一个成功标签。
- 默认两栏，同一 scan_id、同一结果版本和同一 sweep_number。默认最低实际仰角；保留重复仰角和不连续扫层编号，不能把编号当数组下标。
- 前后图同时就绪后再作为一对切换；切站/切扫取消旧请求，禁止晚到响应串图。任一图片失败显示具体错误和重试，不把另一张图错配成新时次。
- 沿用相同 dBZ 图例。质控标记为单独模式；现有 qc PNG 已烧入未决覆盖色，首批不提供不能真实实现的覆盖层开关。
- 站心 PPI 使用距离与方位坐标，可联动缩放/平移。只有核验后的经纬度才显示站点地图落点；没有地理坐标仍可查看站点清单和原生图。不把 PNG 拉伸到地图上。
- X 时间轴按实际体扫排列。资料按约六分钟抽样也保留真实起止时间，缺扫显示间断，不插值、不复制上一扫；不能拿任务 analysis_time 的分钟取整值代替真实观测时间。
- 使用 UTC 存储、UTC+8 展示，日期查询按本地日边界转换。URL 保存 band、station、scan、sweep 和 result，刷新或复制链接可恢复。
- “查看已有结果”是主操作；“生成/重算”作为次要入口，携带当前站点与时间范围进入现有后台预检查流程，查看页面不自动提交计算任务。
- 本期不从 PNG 反推数值，不承诺逐门点查；详情可以追溯 scan、task、版本。精确门值点查需要后续增加极坐标数值接口。

## 数据与接口契约

```text
文件身份清单/站点登记 ─┐
原始与标准化资产目录 ──┼→ Go 只读目录与结果适配 → React X 质控视图
候选任务完成记录 ──────┘             │
                          已校验 manifest/资产代理 → 对象存储
```

先在 `contracts/openapi.yaml` 定义以下新增只读接口，再实现。名称为本方案拟定，并非已存在接口。

1. `GET /api/v1/workspace/radar-stations?band=X&start=...&end=...&cursor=...`：站点身份、名称、波段、坐标核验状态、原始/标准化/候选 QC 数量、资料起止时间。首批每页最多 100 站，返回 available_range，供空日期导航。
2. `GET /api/v1/workspace/radar-scans?radar_id=...&start=...&end=...&cursor=...`：scan_id、真实起止、原始登记状态、独立 qc_status、失败原因、结果版本摘要。时间窗最多 24 小时，每页最多 100 个体扫；排序与游标绑定筛选条件。
3. `GET /api/v1/workspace/radar-products/{result_id}`：固定 task+成功 attempt 身份、scan、站点、版本、候选资格、geometry、legend、comparison.sweeps，以及只读资产 URL。复用原方案 radar-products 详情命名；本批扫描目录直接关联 result_id，不再增加重复产品列表接口。
4. `GET /api/v1/workspace/radar-products/{result_id}/assets/{asset_id}`：资产只允许来自该成功结果的已验证 manifest；保留现有路径、类型、大小和发布标记校验。禁止前端传任意对象存储 URI，也不依赖后台 Token 来读主工作台图件。

Go 从原始登记与 operations 成功记录关联 scan_id；首批不改变原始资料状态，不回填 qc_uri 为候选资产。只有成功且资产可用的结果可进入可对照状态；多版本默认按完成时间选择最新成功版本，并支持固定旧版本。失败的新任务不得遮蔽已有成功结果。

历史候选结果应通过读取现有完成记录直接可发现，无需重新 QC。为选中页面批量查询结果摘要，禁止每个站点或每次翻页全量枚举运行和读取全部 PNG。图件按当前扫层懒加载，仅预取下一体扫对应图对，切站释放旧 Blob URL。

源目录中尚未登记的站点通过现有 ingest/inventory 流程做一次文件身份清单：从实际文件头核对站号/格式/观测时间，记录目录来源；以文件身份而非目录名去重。网页请求不扫描大目录，不自动全量解码。不具备可靠头信息的文件显示待核验原因，不编造站点坐标。

## 交付顺序、范围与验证

第一批一次交付站点目录、扫描目录、候选结果读接口和双栏浏览。先用已经成功的 ZF101/ZF505 贯通，再显示其余已发现站点及未完成状态；原生图不等待空间融合参数核验。这批独立可用，估计 2–3 个开发日加真实资料验收，取决于现有登记覆盖率。

第二批独立扩充数据覆盖：按站点、小时分批登记/解码/六分钟样本 QC，使用现有预检查和 Worker 资源限额；任务完成后浏览器刷新目录即可出现结果。地图覆盖与 S/X 融合仍按原方案的空间资格门控推进，不是第一批的前置条件。

涉及超过 8 个文件：OpenAPI、Go workspace/API 路由与存储查询、结果资产适配及测试，Web MainWorkspace/model、独立 X 浏览组件与数据 hook、候选预览共享组件和 CSS/测试。无需新增服务、账号、密钥或运行时配置开关。复用现有 Go/React/Python 边界，首批不改 QC 算法。

自动验证：`cd apps/web && pnpm test && pnpm build`；`cd services/control && go test ./internal/operations ./internal/controlplane ./internal/workspace ./internal/apiapp`（新增文件所在包同步纳入）；按仓库既有方式校验 OpenAPI。覆盖无预报周期仍能发现 X、无成功结果仍能发现站、版本选择、跨 UTC+8 日界、缺扫、重复仰角、39/40 层、不连续层号、失败重试、旧请求晚到、路径越界、损坏/过期资产、缺测与无雨分离、历史结果幂等关联。

105 人工验收：进入质控排查 → X → ZF101/ZF505，直接看到已有原始/质控后图；切换全部 40/9 层；复制 URL 后恢复相同站/扫/层/版本；无 QC 站明确待处理；空间参数未核验也能看原生 PPI；S 页面正常。截图与真实 API 响应记录为验收证据，不能用“入口出现”代替“有站、有时间、有图”。

最脆弱前提是站点清单能与原始扫描身份可靠对应。若磁盘文件尚未登记，只显示已核对身份的站点，并给出清单未完成状态；补齐清单后才能宣称全部站点可发现。已有两站图件可先独立验收。

发布遵循本地整合、相关测试、本地 main 合并、构建、105 测试部署；推送按用户授权执行。仅追加只读接口与展示，不迁移或覆盖原始/候选产物；回退 Go/Web 构建即可恢复旧界面，保留所有结果资产。
