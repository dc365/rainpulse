# NowcastNet 夜间训练与断点续训运行手册

版本：1.4

日期：2026-09-03

默认训练窗口：Asia/Taipei 20:00 至次日 08:00

## 1. 适用条件

本手册只在 `TRAINING_PLAN_v1.0.md` 的阶段 B、C 使用。阶段 A 的数据审计和预处理不需要停用共享 GPU 服务。

开始夜间训练前必须同时满足：

- 1,000 步 GPU 冒烟已通过；
- 训练服务支持收到终止信号后完成当前优化器更新、保存检查点并退出；
- 最新检查点已经过加载和哈希验证；
- 恢复运行沿用 `run-manifest.json` 中冻结的检查点间隔、批量和加载参数，不能只按当前方案默认值重建命令；
- 数据、检查点和日志磁盘余量通过门槛；
- 训练服务使用含 PyTorch 和 CUDA 的专用训练环境，不能误用通用算法环境；
- 运行训练 timer 的用户已启用 systemd linger；
- 正式恢复使用生成已批准检查点的固定训练代码提交，主工作区更新不能改变该提交；
- Qwen3.8 和 Qwen3.6 的停止、启动和健康检查方式已在服务器侧受控配置中确认；演化阶段只授权停止 Qwen3.8，生成阶段批量 16 授权同时停止两者；
- 当晚没有更高优先级的 GPU 任务；
- 训练窗口、恢复点和预期阶段已写入 `STATUS.md`。

服务器地址、账号、密码和具体服务单元名不得写入本仓库。

## 2. 每晚时间表

| 时间 | 动作 | 必须留下的证据 |
|---|---|---|
| 19:50 | 训练前检查 | GPU 进程、显存、磁盘、数据清单、检查点和代码提交 |
| 20:00 | 按训练阶段停止已授权的 Qwen 服务 | 停止结果、释放后显存；不扩大到 VLLM 或其他服务 |
| 20:05 | 从最新有效检查点启动或恢复 | 运行标识、恢复步数、配置和检查点哈希 |
| 运行中 | 按阶段的时间/步数上限保存 | 检查点加载验证、训练指标和 GPU 资源 |
| 07:45 | 请求优雅停止 | 最后完整优化器步数和停止原因 |
| 07:50 | 验证并镜像最终检查点 | 本地与镜像哈希、可加载结果 |
| 08:00 | 恢复当晚暂停的 Qwen 服务并健康检查 | 服务健康状态、GPU 进程和显存 |

演化阶段检查点条件采用“30 分钟或 5,000 步，以先到者为准”。生成阶段因单个检查点约 0.5 GB 且每步明显更慢，采用“5 分钟或 1,000 步，以先到者为准”，滚动保留最近 3 个，同时永久保留每 10,000 步里程碑和每个训练窗口的最终检查点。

## 3. 训练前检查

按顺序检查，任何一项失败都不启动训练：

1. 仓库提交与当晚计划一致，工作区没有未审阅的训练代码变更。
2. 训练配置、数据清单和样本索引的哈希与计划一致。
3. 最新检查点位于完整目录，不是 `.tmp`，其清单、大小和 SHA-256 一致。
4. 用 CPU 或低显存方式加载检查点元数据，确认网络、优化器、全局步数和随机状态齐全。
5. 本地临时盘能够容纳至少两个完整检查点，镜像盘能够容纳保留策略要求的检查点。
6. 数据盘余量高于冻结门槛，I/O 延迟没有异常。
7. GPU 无未知进程，驱动、温度和错误计数正常。
8. 共享服务当前健康，停止方式可用，08:00 的恢复责任明确。

预检查结果写成结构化 JSON，至少包含 UTC 时间、代码提交、配置哈希、数据哈希、恢复检查点、磁盘余量、GPU 进程和执行人。该 JSON 不含账号、密码或内部服务控制信息。

## 4. 启动与恢复

训练入口只接受三种恢复模式：

- `new`：仅用于一个新模型版本的第一个窗口，要求目标制品目录为空；
- `auto`：正式夜间训练默认值，选择最新且验证通过的检查点；
- `exact`：事故复核时指定检查点哈希，不接受模糊的 `latest` 文件名。

恢复后先执行一个只读校验批次，核对：

- 模型阶段和全局步数；
- 优化器与学习率；
- 下一批样本标识；
- Python、NumPy、PyTorch 和 CUDA 随机状态；
- 连续运行基准中的下一步损失容差。

任一项不一致时停止，不能通过重置优化器或随机种子强行继续。

“精确恢复”指检查点中的模型、优化器、调度器以及 Python、NumPy、PyTorch、CUDA 随机状态指纹与加载后的状态完全一致。当前 CUDA `grid_sample` 反向算子不提供逐位确定实现，因此两次独立训练进程的后续轨迹不要求 bitwise 相等。阶段 B 已冻结短程对照门槛：批次标识必须一致，总损失和累积损失的误差分别不得超过 `max(0.05, 1% × 基准绝对值)`。该容差只用于确认恢复没有引入额外跳变，不得用于掩盖 NaN/Inf、状态哈希差异、批次错位或长期发散。

## 5. 运行中监控

训练进程至少每分钟输出：

- 当前阶段、全局步数和每秒步数；
- 各损失项、学习率和梯度范数；
- GPU 利用率、显存、温度和功耗；
- CPU、内存、数据读取等待和批次耗时；
- 非有限值、跳过样本、数据读取失败和检查点状态。

出现以下任一情况，立即请求优雅停止：

- 损失或梯度出现 NaN/Inf；
- 连续数据读取失败或样本哈希不一致；
- GPU 显存不足、驱动错误或温度超过服务器门槛；
- 检查点连续两次写入或验证失败；
- 磁盘余量低于门槛；
- 共享服务需要紧急恢复。

不要在运行中临时修改批量、学习率、数据范围或损失权重。需要修改时结束当前模型版本或升版配置，再从开发计划重新进入。

## 6. 优雅停止与检查点

07:45 的停止流程固定为：

1. 停止领取新批次。
2. 完成当前前向、反向和优化器更新。
3. 保存全部模型、优化器、调度器、随机状态和运行元数据。
4. 写入临时文件并同步落盘。
5. 在独立进程中执行一次加载验证。
6. 计算 SHA-256，原子重命名为正式检查点。
7. 镜像到训练制品盘并再次核对哈希。
8. 训练进程退出，释放 GPU。

如果 07:50 前未完成，不得一边保留训练进程一边恢复共享服务。优先完成安全停止；超过 08:00 时记录事故，并在 GPU 确认释放后立即恢复 Qwen3.8。

突然断电或进程崩溃时，忽略残留临时文件，从上一个已验证检查点恢复。不得人工拼接损坏检查点。

## 7. 共享服务恢复

训练进程退出后按服务器侧已冻结的方式恢复当晚暂停的 Qwen 服务，并逐一验证：

1. 服务进程正常启动。
2. 健康端点返回预期结果。
3. GPU 显存恢复到日常范围。
4. 无遗留训练进程或孤儿 CUDA 上下文。
5. 服务日志没有模型加载或显存错误。

演化阶段只授权暂停 Qwen3.8。生成阶段批量 16 的短程实测峰值保留显存约为 39.51 GB，仅暂停 Qwen3.8 时安全余量不足；其训练窗口已获授权同时暂停 Qwen3.8 和 Qwen3.6，启动前必须确认两者健康，停止后 CUDA 可用显存不得低于 75 GB。VLLM 和其他服务不在停服范围。

批量 8 的既有峰值保留显存约为 20.54 GB，只作为阶段 B 调试基线，不视为全局批量 16 的等价替代。资源协议通过不等于批准 500,000 步正式训练；正式训练仍需在 1,000 步全父权重演练验收后，由人工签发绑定代码、配置、父权重和起始 checkpoint 的一次性许可。

共享服务恢复失败属于当晚最高优先级问题。此时不开始下一次训练窗口，并在 `STATUS.md` 记录阻塞。

## 8. 每日训练报告

每个训练窗口生成一份不含敏感信息的摘要，至少记录：

- 运行标识、模型版本和训练阶段；
- 开始与结束 UTC 时间；
- 起始、结束和累计全局步数；
- 输入和输出检查点哈希；
- 数据、配置和代码提交哈希；
- 损失摘要、吞吐和峰值显存；
- 停止原因；
- 共享服务恢复结果；
- 下一夜是否允许自动恢复。

只有摘要和小型指标制品可以进入 Git。权重、优化器状态、训练样本和原始日志保存在仓库外。

## 9. systemd 实施要求

正式夜间调度使用 systemd service 与 timer，不使用无人监管的裸 `cron`：

- 训练服务负责启动、信号处理、超时和退出状态；
- 训练服务必须使用 `KillMode=mixed`，让 SIGTERM 先到达主训练进程，再由主进程回收 DataLoader workers；禁止使用会同时终止全部 workers 的默认 `control-group` 模式；
- 短程时限演练优先由能够保留子进程退出码的受控超时包装器发送 SIGTERM；不要仅依赖 `RuntimeMaxSec`，否则训练虽已优雅保存并以 0 退出，systemd 仍会把到时停止记录为 `timeout/failed`；
- 启动 timer 在 20:00 触发预检查和资源切换；
- 停止 timer 在 07:45 请求优雅停止；
- 启动 timer 使用 `Persistent=false`，服务器错过 20:00 后不能在白天补跑；停止 timer 使用 `Persistent=true`，错过停止时刻后仍须优先停止训练并恢复共享服务；
- 首个正式窗口结束后自动关闭下一次启动，人工验收报告和检查点后才能批准第二个窗口；
- 每个窗口使用一次性启动许可，许可绑定输入检查点步数和哈希，资源切换前即被消费；
- 资源守卫确保训练退出后恢复已授权共享服务；
- 训练进程的 `ExecStopPost` 只生成报告并恢复共享服务，不能在 `ExecStopPost` 内控制 timer；timer 的启停由外层停止服务或人工验收动作完成，避免嵌套停止事务互相等待；
- 重启策略不能绕过检查点验证，也不能在数据错误时无限重启；
- 单元名、主机路径和服务控制参数放在服务器侧环境文件，不提交 Git。

systemd 单元实现后，先用受控演练分别执行一次 `new` 和一次 `resume`，验证预检查、定时停止、原子检查点、状态恢复和共享服务回切，再允许进入完整夜间训练。演练检查点必须经过人工批准才能转为正式训练起点。

正式训练批准后，代码身份固定为演练检查点记录的提交。若主分支只增加文档、测试或证据，正式训练仍从固定提交恢复；若训练代码或配置需要修改，停止当前模型版本，升版方案并重新执行恢复验收，不能绕过提交一致性检查。
