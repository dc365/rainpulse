## 1. P0：不再混淆配置审批与测量健康

`quality_policy.health_facets` 不修改原始健康对象。它只投影一个具体、可核实情形：
health=DEGRADED、唯一原因CONFIG_NOT_READY、channel_status=OK。此时新配置的物理乘数为1；
配置仍draft，admission_ready=false，operational_eligible=false。

任何其它原因（包括未知将来原因）、无原因的DEGRADED、通道缺失/非OK都不能获得例外。
NOISE_OUT_OF_RANGE、波束/数据故障等继续使用原物理惩罚。原UNAVAILABLE的上游处置不改变。

`finalize_decision` 同时保存惩罚前QI、旧健康策略资格掩码、实际物理系数、行政惩罚移除掩码。
这些字段表示资格政策变化，不是“已证明天气恢复”。旧阶段本来不可信的测量不能因此重新进入QPE。

本次没有另行实现一个“所有原始观测都可见”的显示模式；业务反射率仍使用现有定量资格规则。
消除行政惩罚只是修正该规则中的健康因素，不是UI隐匿或把掩码去掉。

## 2. P1：测量证据与对象形状分离

`range_signatures(..., route_all_shapes=True)` 增加P2_ROUTE等输出，默认False确保旧调用字节行为不变。
route1=原窄径向，2=宽，3=紧凑，4=宽且紧凑。输出的是原拟合支持内点，未被关联的空洞不赋值。
原最大宽70°/最小长宽比2、原拟合残差2.5dB等阈值都不修改。

新广域复核必须同时具备：实际距离模型支持、OC1 family=2且目标相容、有界目标外参考条件、
原始有效观测、非未核实数值平台，没有独立可比天气或目标局地增强/矩失配冲突。
仅“红、宽、高相关、低相关、相位平稳”都不能单独触发动作。

OC1中的本地BROAD_WEATHER_CONTINUITY仍保留为证据：同一片高相干测量产生的平滑性，
不再被当作独立天气观测自动否决共同源解释。真正可比垂直/邻站支持继续保护。
当前两项模型共享同一接收链，不是两台独立仪器；新动作只做疑似隔离，不新增确认RFI原因。

仍未充分解决的情况包括：目标不在参考两侧、目标本身矩不可用、距离模型不成立、不同源混合、
未核实数值平台等。本版不会为“图更干净”放开这些约束。

## 3. P2：预算与业务准入

配置的10%是实验资格损失复核阈值，不是“允许10%真实天气损失”。
旧OC1因预算整体回退时，新分支只接收其原来明确提出的、实际观测的合格提议，并仍检查独立天气；
不会把未提议区域整扫隔离。`prevent_budget_reversion`可独立消融。

当累计损失超限时，summary.review_required=true，status=isolated_review_required。
有风险的合格隔离不被恢复为正常QPE，operational_eligible始终false。
这是明确的计算结果与人工准入信号；**没有新增一个Go人工签核界面，也没有阻止显式历史测试发布**。
调用者必须把review_required用于验收/推广流程，不能把测试发布成功解释为业务准入通过。

完整路由明细存入受校验QC资产的summary，NATS完成事件只发送原有有界标量、健康分项和复核汇总。

## 4. 开关与同条件消融

新配置：`configs/qc/fujian-qc-generalization-p0p2.yaml`。

- `split_admission_health`：P0政策修正。
- `retain_broad_measurements`：P1保留宽域支持；关闭时仍记录路由但只允许原V5候选进入该动作分支。
- `resolve_coherent_self_protection`：启用共同源测量复核。
- `require_bracketed_reference`：默认true，不对没有两侧参考的边缘外推。
- `prevent_budget_reversion`：保留旧OC1原有合格提议，不因超预算变成正常可用。
- `quarantine_quality=0.2` 与复核损失阈值=0.1：显式工程策略，非气象真值指标。

四个行为开关全false时，在固定前置Decision下原动作/数值/QI一致。每种消融必须保存独立配置SHA，
不要用同一个job ID反复替换不同策略结果。本版保留原renderer1.2.0，不改变6分钟时间线及预测步长。

## 5. 实际重放脚本

```bash
uv run --project algorithms python scripts/replay_qc_generalization_cases.py \
  --input /私有资料/qc-case-2026-08-28-1042-1048-cst \
  --output /新目录/p0p2-nine-cases
```

使用附件README/metadata，核验全部normalized目录脱敏后内容摘要和QC输入摘要。
每例选择原实际最低反射率切面；校验原始DBZH与QC保存值相同、旧距离模型候选逐门相同、
OC1的state/family/reason逐门相同，再以固定的实际垂直/跨站支持数组比较：

1. saved baseline；2.P0-only；3.P1/P2-only；4.combined。

仅重放新增与相关最终阶段：保存QC中受健康惩罚的品质反推到原惩罚前，保持原先局地拒绝/隔离。
反事实baseline资格必须精确复现，QI浮点误差<=1e-7。保存旧flags，不虚构缺失的首设标志。
这**不是完整重建每个历史作业的全部供证过程/全体积**。脚本的真实输入上下文数组已经固定，
不得把它的耗时当作完整Worker P95。实际Worker序列化及下游完整性另用真实库合成数据测试。

重放预算分母是保存的OC1后、健康前资格；实际新Worker另保存真正OC1前资格并计算累计损失。
因此不要把两种分母混称同一个全面历史回放指标。

输出每例raw、baseline、p0_only、p1_p2_only、combined五张640原生采样图，完整增量数组和摘要。
九例9×5张图、HTML索引和选区明细仅随交付包保存，不将私有资料提交仓库。
复核域不是标签：SITE_A为既有高值资格区域，SITE_C小块由原PNG坐标选取后显式扩展，
其它站不当成全站正常真值。代码不依赖这些选区、站别或时次作决定。

排空或隔离旧任务后创建新身份重算；仅合并代码不会替换旧图片。

回退使用原7.1配置/镜像和原规划器选择；新产物不能伪装旧版本。保留原资料和最后可用产品，
不通过清理历史唯一产物强制全量重算。消息大小限制保持不变。

## 7. 风险和未验证项

- 九例没有独立天气真值；新隔离数量不是精确率/召回率，健康政策释放的门不自动等于真实降水。
- 10:48宽扇区仍有较多残留，不能说“全部径向解决”；本版只处理实际模型一致且条件满足的测量。
- P0会影响整切面所有此前受行政折扣影响的门，不仅影响用户红框；报告必须审查全站资格增加，
  并保留真实物理异常的惩罚。
- 不新增原生bRopo/RDD、IQ处理、概率训练模型。保留现有Py-ART/wradlib算法及许可，项目原始数据不公开。
- 完整历史上下文、目标硬件P50/P95、浏览器、真实天气负例和正式推广签核尚待现场验证。
