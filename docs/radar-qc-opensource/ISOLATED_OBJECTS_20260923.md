# 物理尺度、支持感知的孤立对象审查

源码基线：`bd645c381d7321b14d51672cb8e254ba05c6cdb2`。
配置入口：`volume_review.clutter_fusion.isolated_objects`，版本 `isolated-objects-20260923-v1`。
这是源码候选，不是生产验收或部署记录。未改变径向、源族、NMR、既有近站开关、背景资产及架构批次。

## 1. 与论文的关系

借鉴《基于改进卷积技术的雷达回波图像质量控制方法研究》中的周围支持与孤立性思想：
https://html.rhhz.net/BYZH/html/2865.htm

新增检测器不是论文原算法的等价复制。原始极坐标上的观测支持、固定米尺度、天气保护和目标测量条件是本次工程扩展。
两个固定米间距的对角弱回波评分仅供诊断；其和为dBZ数值和，不是线性功率或新反射率。阈值40只产生诊断标记，不参与任何动作。

## 2. 从原始观测提名对象

连通对象来自所有原始有效DBZH、单一结构阈值（默认-10 dBZ）；已被旧QC拒绝的测量也参与结构描述，不拿删除后的图制造新空洞。
对象提取不预先删除强回波、天气或域外门，再将剩余部分拆成小块。
角度排序、内部扫描间隙、重复坏射线、真360度接缝均显式处理；接缝通过对象身份合并，不做填洞。

面积按原始门投影到本站水平面的扇区面积累计，记录 km²。尺度使用实际距离和仰角的4/3地球几何；无绝对地形高度假设。
候选同时限制面积（默认≤4 km²）、包含整个原始足迹的保守直径（≤4 km）及单门分辨尺度（≤1.5 km）。门数上限2000仅是资源/处置上限，不是物理面积替代。

对象包含圆外留250m间隔，分别评价1km和2km宽的环带。250m积分网格用于近似面积比例，不能当成新增观测；另行统计不同原始ray/gate数量。
每个环带要求已知支持≥80%、每象限≥65%、至少12个不同原始门。未知位置按“可能有回波”的最坏情况进入回波占比上界，上界≤20%才算孤立。

已知支持仅来自合法有限原始值或明确的 `Sweep.no_echo`；保留码、NaN、旧QC删除和低质量标记都不能被转换成有效无雨。
**当前NativeSweep→CF适配器没有供应独立no_echo状态，本版没有猜测厂商码表。** 实际运行中没有该状态时，仅能依靠有限实测支撑；缺测周边会导致弃权。
可信DEM严重遮挡不作为清空周边的证据；已有可动作的严重遮挡位会阻止这一分支的孤立判断。未绑定DEM不伪造阻挡结论。

## 3. 保护与原始门条件

原始对象内只要有一个强回波或已存在硬天气、局地天气、旧保护、天气代理、混合或背景增强门，本分支保护整个对象。
邻近天气同时使用积分位置和原始天气门中心/保守足迹范围检查，避免积分网格漏过微小强单体。
多尺度只在同一冻结输入上执行一轮。没有侵蚀、膨胀、去均值、填孔或递归清理。对象只传递保护，不传播删除。

动作门必须自身具备实际SNR/RHOHV和已有CF极化特征：默认SNR≥12dB、极化相容分≥0.65，且低相关特征或可靠DR支持非气象；已有严格部分矩分支也可供证据。
至少60%的原始对象门有当前测量支持；即使超过此比例，缺少自身测量的其他门仍不能被带删。

CR-only允许“可靠孤立结构＋当前非气象测量”的门退出可信最大值。
QPE/trust隔离还需要当前门的稳定背景且当前非气象匹配、严格过去体扫支持、可动作多普勒或垂直证据之一。未确认的跨层观测不升级为动作证据。
不使用强近站膨胀/对象传播结果、回溯未来消失结果作为新增依据。不同极化表达式不被算作多份独立信息。

## 4. 动作与审计

- 缺省无 `isolated_objects`：原参数序列化和摘要不增加该键；旧行为不变。
- `mode: audit`：本分支不改变CR/QPE/trust/QI/flags；父级已启用动作保持原样。
- `mode: cr_withhold`：只限制CR，标记未定覆盖；不改QPE或原始数值。
- `mode: quarantine`：只有额外上下文充分的门走已有CF隔离/派生量失效流程；其余合格候选仍仅限CR。

`CF_ISO_*`保存原始对象编号、原始门数、面积/直径、支持/回波上界、保护、现有测量支持、原因和状态。
`CF_ISO_CR_WITHHELD_MASK`及`CF_ISO_QUARANTINE_MASK`是相对全部原CF/near/strong动作的净新增归因；统一总动作仍在 `CF_CR_WITHHELD_MASK`、`CF_QUARANTINE_MASK`。

证据先在整扫全部切面准备完毕，再统一处置。本分支资源超限时只撤回本分支整扫建议，父级不回退。默认最多20,000对象、8,000,000积分/诊断采样点；不输出半扫新增动作。
每对象环带细节进入已有哈希绑定的 `qc/volume_review/clutter_fusion.json`，完成事件摘要只保留计数和路径，避免大数组/长对象清单挤入控制消息。
已有CF前置状态恢复与序列化验证继续执行；CR通用CF资格泄漏检查继续生效。新增赢家审计工具校验实际贡献值、有效性、资格和拒绝位。

## 5. 配置与验收

```bash
python scripts/make_isolated_object_profiles.py --parent /path/to/actual-active.yaml --output /path/to/new-profiles
python -m pytest -q algorithms/tests/isolated_objects_20260923 algorithms/tests/clutter_fusion_20260921
```

生成器默认调用整套OpenSourceQCProfile与P3模型验证；依赖缺失直接失败。`--schema-only`只用于明确的离线P3模式检查，结果回执标注未完成全配置验证。
不改变其他键，不自动选择运行配置，不部署。父CF审计时只生成审计；父CF不能quarantine时不生成定量隔离档。

必须在完整现场父上下文中做父/子重算，保存实际QC、CR赢家和弱天气标签。没有可靠背景/无雨语义时，正确结果可能是弃权而不是清除。
现有 `volume_review/near_object.py` 的旧CR后置对象审查没有在本次改写；因此孤立新候选数不等同于现场新增可见变化。
