# 径向共享源参考与逐门结果核验

## 1. 基线、目的和改动边界

基线 `dbe3ca8d5df00fea7709b859b4cb3b99b8c1f95a`。配置入口为
`volume_review.receiver_domain.source_family`，默认不存在；不改变旧配置序列化、旧RDR长源和分段源的参数。
本轮只修改接收域径向模块及组合反射率的诊断核验，不改杂波、晴空背景、NMR算法、Go、React或部署默认配置。

针对的问题是：邻近射线已经有稳定相干源参考，但边缘射线自身混有不同距离状态，不能独立通过旧长源/分段模型。
不使用截图颜色、固定方位、站名、时次、目标区域或原QC删除标签训练。
“源族”仅指同一切面、同一留出折的相容测量对象，不代表识别了实际发射设备，也不代表邻近观测互相独立。
本实现提供距离有序的支持块/连续段与有界重复状态归并，不是全体积HMM或通用所有干扰类型的模型。

## 2. 判别顺序

1. 先完整执行旧RDR长源与已有分段路径，冻结其模型可用域和结果。
2. 新路径仅评价旧RDR没有可用模型的位置。已有模型明确不匹配的位置不再通过借用参考重试。
3. 在实际角距离、仰角差、采集时间及几何连续性限制内寻找邻近射线。至少两条原始射线必须各自通过旧严格长源拟合；全部捐赠模型须两两相容，不按目标误差挑选最好的一组。
4. 捐赠参考排除整个目标射线作为捐赠者或侧翼，同时排除目标距离块及其两侧保护块，范围覆盖所有射线。不得递归使用共享模型或新隔离结果作捐赠者。
5. 共享相位、ZDR、相关系数范围及接收距离关系；不共享强度。目标射线的幅度和受限偏置由它自身的训练端实测估计。
6. 目标训练区按物理距离块组织，保留原距离顺序。缺口、目标/保护块和变化状态截断连续段；重复稳定段允许有界归并，但记录真实区间，绝不填缺口。
7. 幅度与偏置采用物理块之间双向留出预测核验。所有参考与状态在读取目标匹配结果前完成。当前目标必须恰好匹配一个状态。
8. 目标自身的反射率、SNR、极化须满足匹配条件；目标距离处至少两条原始捐赠射线也要具有完整相容实测；实际束外两侧SNR必须有值且有反差。捐赠门若被独立天气或来源不明保护否决，不计入当前支持。
9. 将结果交给原RDR的独立天气、局地相干性、未知保护和统一处置。不存在单独的“源族删除掩码并集”阶段。

默认新模型采用3°邻近角距离、2km支持块、每块至少1km实际支持、累计至少4km、至少2个支持块；目标幅度偏置最多1dB。
这些是版本化开发参数，不是已校准的气象标准。其它严格目标阈值继续取实际父配置。

## 3. 处置档位

| 子配置 | 新路径动作 | 旧RDR动作 |
|---|---|---|
| audit | 仅记录证据，不改任何数值资格 | 原样保留 |
| full-cr | 完整匹配且通过保护的门退出可信CR | 原样保留，包括原有隔离 |
| full-quarantine | 完整匹配按父级允许的隔离强度执行；关闭信任/QPE并使相关派生段失效 | 原样保留 |
| partial-cr | 完整匹配和合格部分匹配退出CR；部分匹配不产生QPE隔离 | 原样保留 |

父级为audit时，新路径不能执行动作；父级为CR-only时，新路径不能提升为定量隔离。
数值尾部、已存在极化反证、实测侧翼冲突和独立/未知天气保护仍阻止不合理升级。
未决源风险只增加风险记录，不自动将所有未知观测从CR移除。部分资料仅限显式选择的CR档。

## 4. 逐门记录与CR来源

`RDR_FAMILY_REASON`记录尝试、参考不足、状态不足、模型歧义、功率/极化冲突、缺极化、尾部、缺少同距离捐赠、侧翼缺测/冲突及天气否决。
`RDR_FAMILY_OBJECT_ID`与`RDR_MODEL_ID`关联同一切面、留出折的嵌套参考记录。
记录包含捐赠射线、每条捐赠的原始侧翼、目标自身各状态实测区间、双向留出预测和原始观测哈希。
适配器把包括嵌套捐赠/侧翼在内的**索引值**转回原采集顺序；哈希仍明确指向原拟合顺序的观测记录，不伪称转换后字典的字节哈希相同。

组合数值产物新增：
- `CR_RECEIVER_FAMILY`：原始源族完整/部分匹配反射率最大值，诊断用；
- `CR_RECEIVER_FAMILY_UNRESOLVED`：已建立源参考但仍未决的风险数值；
- `CR_RECEIVER_FAMILY_WITHHELD`：本路线实际排除的CR贡献诊断；
- `WINNER_RECEIVER_FAMILY_OBJECT_ID`、`WINNER_RECEIVER_FAMILY_REASON`：赢家对应门的源族原因，需结合已有雷达/切面/ray/gate索引解释。

不能把被排除或无剩余可信贡献的位置填成零雨量。最高值被移除后，所有接替贡献也必须自身有资格。
混合新旧源族配置的多站输入拒绝进行可信CR合成。React控件未在本次新增。

## 5. 资源和旧校验兼容

计数限制覆盖新路线拟合折、捐赠尝试、物理支持块和对象数。若任一切面触发新源族资源上限，整站体扫丢弃所有新源族结果，重新执行不含新路线的冻结父RDR，保留父级的原有动作，并明确记录 `RESOURCE_ABSTAINED_PARENT_RETAINED`。
不允许保留“前几层新路线成功、后几层回退”的半成品。原RDR自己的既有资源退化策略不改变。

沿用RDR精确`BEFORE`状态和原验证链。新验证检查：没有接管旧可用模型、所有目标有实测支持、唯一状态、同距离捐赠与侧翼、参考留出、天气否决及动作等式。
不是放宽旧校验器来迁就新隔离。

## 7. 使用

```bash
python scripts/make_receiver_family_profiles.py \
  --parent /data/frozen-active-qc-parent.yaml \
  --output /data/receiver-family-profiles

# 独立的原始源分支对照；不要称为完整QC。
python scripts/replay_receiver_family.py \
  --cases /data/bjt1530 /data/qc-case-bjt0900 /data/qc-case-bjt0912 \
  --parent /data/frozen-active-qc-parent.yaml \
  --output /data/new-source-family-raw-replay --portable-reader
```

现场先运行audit，再比较full-cr，最后审核full-quarantine。应保持完全相同的父上下文、输入、杂波及背景配置，并重新生成带完整门级数据的QC和组合产物。
