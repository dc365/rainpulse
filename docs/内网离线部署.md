# RainPulse 内网离线部署

本文用于将已构建、已验证的 RainPulse BDP 4.0 部署交付到无法访问镜像仓库的内网主机。离线包只包含程序镜像和运行配置，不包含雷达、静态地理数据、模型、数据库或产品结果。

## 同时携带历史案例（如8月28日）

历史案例单独打包，不能只拷贝图片：包内包含当前可用产品关联的数据库记录、QPE/质控图层、LK产品、STEPS和NowcastNet产品及点值索引。依赖记录可能包含起报之外的时刻，但不会复制原始雷达文件、训练资料、模型权重或任务队列。日期默认按北京时间（UTC+8）解释。网页在线底图瓦片不在包内，纯内网可关闭底图；内网底图服务需另外配置。

在105的部署根目录执行（需要Python 3.10+、Docker权限）：

```bash
bash scripts/package_history_case.sh --date 2026-08-28 \
  --output .build/rainpulse-case-2026-08-28.zip
```

脚本不会覆盖已有ZIP。重新打包时指定新的输出文件名即可。导出期间避免重算；若当前产品切换、文件缺失或出现凭据类字段，导出会失败，不会生成成功ZIP。仅原有analysis-fallback提示会记录在包内。

将程序包、案例ZIP及两者的`.sha256`一起拷贝到内网。先按下文安装基础栈，保持雷达采集和流水线关闭；纯回放环境将`RAINPULSE_ADMIN_TOKEN`留空，禁用后台重算入口。**目标库必须没有案例数据**，导入器拒绝合并、覆盖已有案例。

```bash
sha256sum -c rainpulse-case-2026-08-28.zip.sha256
unzip rainpulse-case-2026-08-28.zip -d rainpulse-case-2026-08-28
bash rainpulse-case-2026-08-28/import_history_case.sh \
  --package rainpulse-case-2026-08-28 --verify-only
bash rainpulse-case-2026-08-28/import_history_case.sh \
  --package rainpulse-case-2026-08-28 --root /内网/RainPulse部署根目录
```

`--root`指包含`deploy/docker-compose.yaml`和`deploy/.env`的程序部署根目录，真实密码仍只从内网自己的`.env`读取。导入前停止应用/调度/worker服务，只运行基础设施，例如在程序部署根目录执行：

```bash
docker compose --env-file deploy/.env -f deploy/docker-compose.yaml stop
docker compose --env-file deploy/.env -f deploy/docker-compose.yaml \
  up -d --no-build --pull never postgres migrate minio minio-init \
  minio-versioning minio-worker-user minio-worker-policy-create minio-worker-policy
```

等待初始化服务成功退出，再运行上述导入命令。完成后用`bash install.sh --mode base --replace-existing`启动基础栈，使文件产品与数据库同时对外可见。数据库记录在同一事务提交；失败不会覆盖现有对象，同内容对象允许复用。若在复制文件阶段失败，可修复原因后重试；不要在部分导入时启动Web/API。

导入后在“历史案例”选择2026-08-28，检查时次、四图、时间轴及点值。这属于已生成结果回放，不需要GPU；后台重算不可用（缺少原始输入与模型），不能开启实时采集来代替案例导入。

注意：程序打包仍从Git提交取`deploy/configs`，镜像来自Docker本地库。交付前须统一已提交配置与已构建镜像；单独生成案例包不会重新编译程序，也不会把未提交配置自动并入旧程序ZIP。

2026-09-09验收：105已生成`.build/rainpulse-case-2026-08-28.zip`及校验文件，123个时次、57,035个文件，ZIP为3,238,273,996字节（约3.24GB）。ZIP和逐文件哈希校验通过；在独立空PostgreSQL数据库中完成全部记录插入和外键检查后回滚，没有向105业务库导入数据。9项工具单元测试通过。完整内网Web启动仍需在目标机按上述步骤验收。

## 交付边界

离线 ZIP 包含：

- 当前 Compose 所需的 Docker 镜像归档；默认同时包含基础栈与 `realtime-shadow` 覆盖层；
- `deploy/` 中的 Compose、迁移、NATS、MinIO、Prometheus 和 Alertmanager 配置；
- `configs/` 中的雷达、质控、格点、拼图、预报和产品配置；
- 安装脚本、校验脚本、镜像清单和 SHA-256 清单；
- 不含真实 `deploy/.env`。包中仅保留无密钥的 `.env.example`。

`deploy/nats/data/.keep` 与 `deploy/minio/data/.keep` 是 Compose 所需的空目录占位文件，不含任何运行数据。

下列内容明确不进入离线包：

- BDP 配置目录、配置中心凭据、文件服务凭据和任何密码、令牌；
- 雷达基数据、DEM、海岸线、陆海掩膜、静态杂波图和其他静态资料；
- MRMS、训练样本、NowcastNet capsule/权重、离线验证结果；
- PostgreSQL、NATS、MinIO 卷，以及已生成的分析和产品目录。

因此，基础模式可以在无气象数据时启动并提供空态 Web/API；启用实时影子链路前，必须单独完成雷达与静态资料挂载。

## 生成离线包

在已连接镜像仓库、并且已经完成 BDP 4.0 版本构建和 Compose 部署的构建机运行：

```bash
cd /home/yons/hwapp/ruiyun-bdp/bdp-dp/bdp-dp-rada/bdp-dp-rada-rainpulse
bash scripts/package_airgap_deploy.sh \
  --output .build/rainpulse-airgap-$(git rev-parse --short=12 HEAD).zip
```

脚本会从 Docker 本地镜像库导出 Compose 所需镜像。普通用户没有 Docker socket 权限时会请求 `sudo`，但不会保存 sudo 密码。生成后拷贝以下两个文件到内网：

```text
rainpulse-airgap-<git-sha>.zip
rainpulse-airgap-<git-sha>.zip.sha256
```

可使用 `--base-only` 缩小包体积；该包不能用于后续启用 `realtime-shadow`。

> 当前 105 主机缺少 Go、Node、pnpm、uv 和 BDP 公共 Go 源码，不能作为重新构建 BDP 程序的构建机。它仍可在管理员 Docker 权限下导出已经部署的镜像。若镜像不完整，应在具备 BDP 4.0 公共源码、构建工具链和网络访问的 Linux/amd64 构建机完成构建后再导出。

## 内网主机前置条件

- Linux `x86_64`，Docker Engine 和 Docker Compose；
- `bash`、`unzip`、`sha256sum`、`curl`；
- 建议至少预留 20–30 GB Docker 与运行空间；
- BDP 4.0 配置目录已经由平台部署，并可被容器只读挂载；
- 已在 BDP 配置中心创建或更新程序配置 `bdp-dp-rada-rainpulse`；
- 管理员已创建独立的 `deploy/.env`，填入 PostgreSQL、NATS、MinIO 所需密钥。

程序运行不需要安装 Go、Node、pnpm、uv 或 BDP 公共 Go 源码；历史案例导入工具另外需要 Python 3.10+，仅用标准库，无需联网安装依赖。

## 安装基础栈

```bash
sha256sum -c rainpulse-airgap-<git-sha>.zip.sha256
unzip rainpulse-airgap-<git-sha>.zip
cd rainpulse-airgap-<git-sha>
cp deploy/.env.example deploy/.env
chmod 600 deploy/.env
```

编辑 `deploy/.env`：填入七个必填密钥，并把 `RAINPULSE_BDP_CONF_HOST_ROOT` 设置为内网 BDP 4.0 配置目录。首次无数据部署时保持：

```dotenv
RAINPULSE_RADAR_INGEST_ENABLED=false
RAINPULSE_PIPELINE_ENABLED=false
```

随后加载并启动基础栈：

```bash
bash install.sh --mode base
```

安装程序会校验包内全部文件的 SHA-256、加载镜像、禁止联网构建或拉取，并等待 Compose 健康检查通过。若目标机已有同名 RainPulse 镜像或服务，默认拒绝覆盖；确认升级时才显式添加 `--replace-existing`。
安装脚本实际执行 `docker load --input images/rainpulse-images.tar`，随后以 `docker compose` 的 `--no-build --pull never` 参数启动服务。

## 启用实时影子链路

实时模式必须先提供以下外部依赖：

1. BDP 配置目录与 `bdp-dp-rada-rainpulse` ProgramConfig；
2. `deploy/.env` 中 `RAINPULSE_RADAR_DATA_ROOT` 指定的绝对目录，须覆盖 BDP `RADA_L2_FMT` 元数据解析路径；默认兼容现有 `/data/Weather/RADA/RADA_L2_FMT/OBS_TEMP`。配置层次、宿主机与容器路径说明见 `deploy/README.md`；
3. DEM、海岸线、陆海掩膜等静态资料，并在 `.env` 中设置对应挂载根目录；
4. 已完成的 `.env` 密钥与端口策略。

满足后执行：

```bash
bash install.sh --mode realtime-shadow --replace-existing
```

`NowcastNet` 官方 capsule/权重属于独立的离线研究运行时，不随本包交付，也不阻断基线短临链路。

## 验证与回滚

```bash
bash verify.sh --mode base
# 或
bash verify.sh --mode realtime-shadow
```

校验会读取 Compose 状态，并验证本机 API 的 `/api/v1/system/status` 和 Web 首页。停止本次服务使用对应 Compose 文件执行 `down`；不要使用 `down --volumes`，以免删除后续运行产生的 PostgreSQL、NATS 或 MinIO 持久卷。
