# 质控排查布局简化与模式崩溃修复（2026-09-29）

## 背景

用户反馈 `/?preset=qc` 质控排查界面"稍显凌乱"，要求简单、直接、清晰。
审查 105 实际界面时另发现：`mode=overlay`（多站叠加）与 `mode=fusion`（组合反射率）
从 URL 直达时稳定触发整页错误边界（"页面暂时无法打开"），仅单站验证可用。

## 崩溃根因与修复

- `RadarQCWorkspace` 在 overlay/fusion 模式下，数据尚未返回时 `activeTime` 为**空字符串**；
  `selectedTime={activeTimelineTime??null}` 使 `''` 原样传给 `SharedTimeline`。
- `SharedTimeline` 中 `activeValue = values[activeIndex] ?? selectedTime ?? issueTime`，
  `values` 为空时落到 `selectedTime=''`，`new Date('')` 为 Invalid Date，
  `Intl.DateTimeFormat.format()` 抛 `RangeError: Invalid time value`，整页被 RouteBoundary 卸载。
- 单站验证模式首帧 `sCycle?.issue_time` 为 `undefined`（可回退 issueTime），因此不崩溃；
  既有测试都带 `&time=` 参数，掩盖了该路径。
- 修复：`selectedTime={activeTimelineTime||null}`（空串视为未选择，回退 issueTime）。
  回归测试：overlay 无 `time` 参数直达渲染（`RadarQCWorkspace.test.tsx`）。

## 第七批：切换时效地图闪白消除

用户反馈每切换一次时效地图闪一下。根因与修复：

- **单站 S**：新周期详情在途时 `frame` 瞬时 undefined → `RasterGISMap.imageUrl`
  变空 → `setSource(null)` 清空。SMap 增加 stale-while-revalidate：详情加载期间
  （`sDetailPending`）保留上一帧显示；确定无帧（详情已到仍无匹配）才显示空态。
- **单站 X**：两个断点——`radar-products` 在途导致 `XMap` 整体卸载渲染"缺少地图图件"
  占位；`useXPair` 重载期间返回 undefined。xResult 按站点保留上一份结果；
  useXPair 增加站点 scope，重载期间返回上一对图件路径（切站时重置，不跨站串图）。
- **多站叠加**：换层原先先移除旧层再异步加载新层。改为先叠加新层，图片资源就绪后
  再移除旧层（RasterGISMap 多图层 effect）；加载失败保留旧层并上报 layerError。
- 实测方法：对地图画布做像素方差高频采样（方差骤降≈空白帧）。105 实测 S 模式
  最低方差为加载态 97%、X 96%、叠加模式全程无下降——切换无闪白。
- 全量 155 用例 + build + lint 基线通过；顺带修复了此前编辑遗留的重复"资料详情"
  节点与一个多余闭合标签。

## 第八批：X 单站与组合反射率的残余闪烁

用户复测：S 单站/多站叠加已不闪，X 单站与组合反射率仍闪。视口标记探针（给
`.ol-viewport`/canvas 打标记，切帧后检查是否被替换）+ 方差采样定位：

- **X 单站**：地图未重建、无空白——闪源是 `useXPair` 先 fetch→blob→decode 校验再返回
  路径的额外一跳，换图延迟超过 800ms 触发"正在切换时效"浮层弹出又消失。修复：
  useXPair 改为从 sweep **同步派生**图件路径（校验/错误交由地图层 imageloaderror 处理），
  行为与 S 完全一致；同时切时次不再重置用户选择的仰角（与 S 一致）。
- **组合反射率**：切时次时产品图层瞬时清空 → `fitExtent` 在 DOMAIN 与产品范围间翻转
  → **整个 OpenLayers 地图销毁重建**（探针确认 viewport/canvas 被替换）。修复：
  MultiStationMap 按 `result_id` 保留上一份组合清单（stale-while-revalidate），
  fitExtent 稳定，换层走多图层"就绪再移除旧层"路径。
- 渲染期状态调整以稳定标识（result_id）比较，避免引用比较在 mock/派生对象下的死循环
  （MultiStationMap.test 曾触发 Too many re-renders）。CompositeMap 导出
  CompositeProduct/CompositeResult 类型。
- 105 实测（视口标记+方差）：X 单站 min 98.6%、组合反射率 min 98%，均无重建、无浮层。
  全量 155 用例 + build + lint 基线通过。

## 第九批：组合反射率 09:06 后切换无变化

用户反馈组合反射率 09:06（北京时）之后切时次完全无变化。根因是第八批的
stale-while-revalidate 逻辑缺陷：组合产品只生成到 09:06（API 确认 01Z 后
`radar-composites` 为空），之后的时次 `useComposite` 返回"已确认无组合"
（state 到达、data 为空），而保留逻辑没区分"在途"与"确认无"，把最后一份组合
永久留在屏幕上。修复：仅当 `compositeState === undefined`（请求在途）时使用
保留清单；确认无组合立即回到"已发布 S 产品"回退路径。

新增回归测试：有时次显示产品层、切到无组合时次后产品层消失且回退文案出现。
105 实测 08:54（组合存在，"S 与 X 贡献…"）→ 10:00/12:00/15:00（回退"现有 S 数值
组合产品"，截图确认各时次画面有实际回波且不同）。全量 156 用例 + build + lint
基线通过。

## 第十批：组合反射率回退区（09:06 后）切换闪屏

用户反馈 09:06 后组合反射率每次切换再闪一下（第九批让切换恢复后暴露）。根因：该区
显示的是"已发布 S 拼图"回退层，来自**逐周期详情**——切时次时新周期详情在途 →
回退层瞬时清空 → fitExtent 在 DOMAIN↔产品范围翻转 → 整图销毁重建（与第八批组合
路径同源）。

修复（MultiStationMap）：回退层同样 stale-while-revalidate——新周期详情在途时保留
上一帧回退层；首次从组合区进入回退区时以保留的最后一份组合 S 产品兜底；详情到达
后立即换新（确认无帧则清空，不冻结）。新增回归测试：受控延迟的周期详情下，切换
期间旧回退层保持、到达后换新且旧层消失。

105 实测回退区（13:12–16:00 连续切换）：视口/画布零替换、图层数全程 1 不清空；
时间轴随切更新（14:42 等）。全量 157 用例 + build + lint 基线通过。

## 第十一批：组合反射率残余"闪"的最终定位与修复

用户复测回退区（09:06 后）仍闪。逐帧双画布哈希探针（底图 canvas = 视图跳变检测器，
内容 canvas = 空白/回放检测器）定位两个残余源并修复：

1. **在途窗口回放旧组合**：组合清单请求在途时，旧保留逻辑把最后一份 09:06 组合
   临时放回（第十批守卫只拦"确认无"未拦"在途"），每次切换闪现旧组合图再回到拼图。
   修复：`compositeMemory` 记录上次确认状态（have/absent），仅上次确认为"有"时才在
   在途期间保留；回退区确认无组合后，在途窗口不再回放。同时删除跨区过渡兜底
   （keptCompositeS），彻底消除该泄漏类。
2. **逐帧产品范围微变导致视图重定位**：全范围重建后拼图/组合产品逐帧 bounds 随参差
   站覆盖微变（实测 10:30 与 10:36 两帧 bounds 不同），地图取景从图层范围实时计算
   → 每次切帧视图重新 fit（缩放/中心跳变）。修复：冻结首次取景范围（渲染期
   setState 模式），切帧不再自动重定位；「定位产品」按钮仍可手动重定位。

105 实测（+1/+5/+30/-7 四档距离）：每次切换仅"旧帧→新帧"两态，底图哈希恒定
（视图零移动），无空白帧、无回放。全量 157 用例 + build + lint 基线通过。
